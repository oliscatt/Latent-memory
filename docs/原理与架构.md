# 原理与架构

这份文档解释 Latent 的数据如何流动、各层分别负责什么。它不是 API 清单；具体命令见
《快速上手》，自建宿主的请求拼装见《注入契约》

## 一条完整链路

```text
已有的人格文件／历史导出／冷启动回答
                    │
                    ▼
       初始化：inspect → extract → choose-sections
                    │
                    ▼
           preview → route → ship
                    │
        ┌───────────┼───────────┬───────────┐
        ▼           ▼           ▼           ▼
     人格文件      记忆库      未解决清单    会话线索
    （每轮常驻）  （按需检索） （换窗优先） （历史快照）
        └───────────┼───────────┘
                    ▼
     latent_ 七工具 → 宿主模型 → 写回／纠错／精准清理／未解决清单维护
```

初始化是一次性的 CLI 流程；运行期是 MCP 服务。两者分开，是因为人格候选与原文删改需要用户
逐节确认，不能藏进一次工具调用里自动完成。

## 四层数据

| 层 | 放什么 | 何时进入上下文 | 主要落点 |
|---|---|---|---|
| 人格文件 | 身份、相处原则、里程碑索引、检索约定 | 每轮常驻 | `CLAUDE.md`、`AGENTS.md`、Grok agent 或 `persona.md` |
| 记忆库 | 已发生事件的完整叙述与当下状态 | 查询相关时按需返回 | `memory/timeline/*.md` 与独立索引摘要目录 |
| 未解决清单 | 当前仍明确没有结束的事项 | 新会话开场优先返回 | `memory/未解决.md`（不进普通检索） |
| 会话线索 | 上次聊到哪、窗口结束时的状态 | 新会话开场，明确标作历史快照 | `threads.jsonl` |

人格文件不追加会话流水账；会话线索也不冒充长期事实。检索命中的正文会带来源与时间信息，
纠错通过撤回账本降低旧说法的检索资格，而不是静默改写历史文件。

## “知道该查”与“查得到”

MCP 服务只负责“查得到”：接收查询、融合检索、返回带来源的片段。人格文件负责“知道该查”：
当用户提到过去、称呼、共同经历或未完事项时，先调用 `latent_search`，而不是凭当前上下文猜。

只有工具没有人格约定，模型可能从不主动调用；只有人格约定没有检索服务，模型知道该查却拿不到
正文。两半缺一不可。宿主若不能自动加载人格文件，需要把出货的人格内容手工放进 system prompt
或等价位置。

## 运行期七工具

| 工具 | 职责 | 是否写盘 |
|---|---|---|
| `latent_session_start` | 新会话召回最近线索与相关块 | 否 |
| `latent_search` | 按用户问题检索记忆 | 命中权重可能更新 |
| `latent_append` | 写入新记忆、当下状态与索引摘要；`mode=preflight` 时只复用计划与校验 | 默认是；预检否 |
| `latent_correct` | 登记纠错／撤回关系，避免旧说法继续浮现 | 是 |
| `latent_cleanup` | 按稳定 recordId 预览并精准清理一条误写，先隔离备份 | 是 |
| `latent_unresolved` | 显式新增、更新或关闭当前未解决事项 | 是 |
| `latent_thread_close` | 保存本轮历史快照，并可复核未解决清单 | 是 |

工具名统一带 `latent_` 前缀，避免与宿主自带的通用记忆工具撞名。stdio 与 Streamable HTTP
只改变传输方式，不改变七工具语义。

## 检索结构

默认零依赖档融合三路排序：

1. BM25 字符 bigram 词面检索；
2. 语义路；零依赖时仍是字符 bigram 余弦，与词面路高度重合；
3. 基于共享显著词的关系图谱路。

三路用 RRF 融合。只有安装本地 `fastembed` 或配置云端 embedding 后，语义路才获得独立的
向量信号。未标定的 embedding 模型可以参与排序，但不能单独放行候选。

检索返回结果不等于“库里有答案”。当前实现仍不能可靠判断库中完全不存在某件事；宿主最多做
一次更具体的改述重查，仍对不上就应明确说没找到。

## 主要模块

| 模块 | 职责 |
|---|---|
| `memory_init.py` | 初始化状态机、确认关卡与出货 |
| `persona_compiler.py`／`persona_template.py` | 人格来源分级、十二节骨架与确认规则 |
| `memory_import.py`／`draft_extraction.py` | 导入翻译与候选提炼 |
| `memory_retrieval.py`／`embedding_provider.py` | 检索、图谱、向量提供方与缓存 |
| `session_thread.py`／`session_recall.py`／`unresolved_state.py` | 会话历史快照、未解决清单与换窗召回 |
| `mcp_server.py` | MCP 协议、stdio／HTTP、鉴权、体检与七工具接线 |
| `reference_host.py` | 自建宿主的最小可执行规格 |
| `e2e_smoke.py`／`regression_set.py` | 接缝冒烟与公开合成回归尺子 |

## 不承诺的边界

- Latent 不是聊天客户端，也不替宿主保存完整会话 UI 状态。
- 自检证明代码路径具备，不证明某个闭源客户端一定接得上。
- 合成回归集证明变化可见，不等于真实用户语料上的通过率。
- 本地优先描述的是默认存储与检索路线；召回正文进入云端聊天模型时，内容仍会离开本机。
