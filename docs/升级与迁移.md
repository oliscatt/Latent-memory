# 升级与迁移

首个正式版本之前，Latent 以 commit 迭代，没有稳定 tag。不要只写“最新版”；复现或报告问题时
记录完整 commit。正式 tag 发布后，本页以 tag 为升级边界。

## 升级前

1. 停止正在运行的 MCP 进程，避免升级时仍有写回。
2. 记录当前 commit、Python、客户端、启动参数与语料绝对路径。
3. 备份整个用户产出目录，而不是只备份人格文件。至少应包含人格、`memory/`、独立索引目录、
   `threads.jsonl`、`init_state.json`、`mcp-config.json` 与 sidecar。
4. 确认备份可以读，不要用“复制命令退出码为 0”代替抽查内容。
5. 如果源码目录有手改，先提交到自己的分支或另存补丁；不要直接用上游文件覆盖。

用户产出最好与 Latent clone 分开放。仓库自己的 `.gitignore` 会忽略人格与记忆文件，把产出
放在 clone 里既容易误判“已经进 Git”，也让源码升级和私人数据混在一起。

## 更新源码

使用 Git clone 的用户：

```bash
git status
git fetch --tags origin
git pull --ff-only origin main
```

正式版本发布后，生产环境优先检出明确 tag，而不是长期跟随会变化的 `main`：

```bash
git checkout <发布标签>
```

如果是下载压缩包或手工复制，必须替换完整 `src/`，不要只拿 `mcp_server.py`。模块之间有直接
import 和共享契约，缺一个文件可能在启动时才报错。

## 升级后验证

先验证公开代码自身：

```bash
python tests/run_release_checks.py --json-out release-checks.json
```

再对用户自己的目录做只读体检：

```bash
python src/mcp_server.py --doctor --corpus <语料目录> \
  --index-dir <索引摘要目录> --threads <threads.jsonl>
```

最后在客户端核对：工具列表中是五个 `latent_` 名称；调用 `latent_session_start`；用一条不会
泄露私人内容的问题调用 `latent_search`。只有代码自检、目录体检和客户端调用三层都通过，
才算升级完成。

## 从早期版本升级时重点检查

### 工具名前缀

早期配置或人格文件可能写着无前缀工具名。当前名称是：

```text
latent_session_start
latent_search
latent_append
latent_correct
latent_thread_close
```

客户端配置、人格文件、`CLAUDE.md`／`AGENTS.md` 和 hook 中写死的旧名字都要同步更新。

### 绝对路径

当前出货配置应给 server、`--corpus`、`--index-dir` 和 `--threads` 使用绝对路径。相对路径会随
客户端工作目录变化，常见表现是服务正常启动却读到另一套空目录。

### 索引摘要目录

未配置 `--index-dir` 时，`latent_append` 兼容写入 `<corpus>/index`；新部署推荐显式配置独立
索引目录。迁移时先确认旧摘要在哪，再改配置，不要留下两套同时增长的索引。

### 时区

未配置时默认 `Asia/Shanghai`。记忆所有者不在东八区时必须显式设置 `--timezone`；Windows
使用 IANA 名可能需要 `tzdata`。时区会影响文件名、标题、检索标签和跨日归窗，不是显示选项。

### 检索路线

不要为省依赖直接从配置删掉 `--embed`。出货配置必须与初始化时用户选择的 `zero-dep`、
`local` 或 `cloud` 路线一致；要换路线，重新明确数据去向后再更新配置。

### 已有人格与旧状态

初始化器能识别 legacy v1 状态，但升级不会替用户猜如何处置成熟人格。重新运行 `inspect` 时，
按实际选择“编译增强”“原文件直接使用”或继续旧流程；出现整节消失、未确认删改或版本过期时，
按错误出口处理，不要绕过 ship 闸门手工复制预览文件。

## 回滚

回滚源码不等于回滚数据。新版本运行期间可能已经写入新的 timeline、sidecar 或状态字段；因此：

1. 停止服务；
2. 保留故障现场的只读副本；
3. 恢复升级前的整套用户产出备份；
4. 检出原 commit／tag；
5. 重新运行该版本自带的自检与目录体检。

没有升级前整套备份时，不承诺旧版本能理解新版本写下的所有状态。不要用局部覆盖制造一套
“代码是旧的、sidecar 是新的”混合环境。
