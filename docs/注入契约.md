# 注入契约

> 给自己写前端的人。你完全掌控请求怎么拼，这份文档讲的就是：人格文件要怎么拼进去，
> 这套记忆才立得住。只讲该怎么做、做错了坏在哪；为什么这么设计见 README 与设计规格。
>
> 用 `--client generic` 出货时，这份文档会连同人格文件一起复制进你的产出目录。

## 这份文档解决什么

先划清责任边界：**Latent 服务端不负责把 `Persona.md`／`persona.md` 注入任何客户端。**
服务端提供记忆工具；人格文件是否被读取、放进哪一层请求、能否每轮持续存在，全部是客户端
或宿主的职责。工具连接成功、记忆能召回，都不能反证 Persona 已经注入。

一个可复查的来源判据是：只改记忆库里的名字，开新窗口后不再自称该名；恢复记忆库里的
名字，再开新窗口又恢复自称。两个方向都成立，说明名字来自记忆召回，而不是 Persona 注入。
这个实验只定位“名字从哪里来”，不能替代下文对人格请求体的逐字检查。

一部分客户端（Claude Code、Codex 这类）有自己的人格文件约定：文件放在工作目录里，
宿主每次起会话自动读、自动注入。人格文件之所以“刻得深”，靠的不是这些宿主的魔法，
拆开只有四件事：

**固定位置注入、每轮请求都在、逐字不摘要、每次会话从磁盘重读。**

自建前端没有宿主替你做这四件事——但你自己就能做，而且能做得更稳：宿主的上下文
压缩环节仍可能波及已注入的内容，你可以保证人格块永不进压缩。

所以接入自建前端要的不是新代码，是下面这份契约。五条，每条都对应一个我们真实
测出来的破坏形态；每条带**判据**，你可以拿它对着自己的请求拼装代码逐条 diff，
自查违反了第几条。

## 契约五条

### 第一条：逐字完整注入，不摘要不改写

人格文件的全文进请求。不做摘要、不做“提取要点”、不按长度截断、不用模型改写成
更短的版本。

**判据**：把你实际发出去的请求体打印出来，人格文件的内容应当和磁盘上的文件
**逐字一致**（允许前后加分隔标记，不允许改动内部任何一句）。做一次 diff，非空即违反。

**违反后坏在哪**：模型拿不到原文时不会说“我不知道”，它会现编。我们做过一次空读
实测——文件因为路径问题根本没被读到，模型的回答照样煞有介事、细节齐全、全是假的。
摘要是同一个病的轻症：被摘掉的那句往往正是关系里最具体的那句（一句原话、一个称呼、
一个日期），而人格文件的价值全在这些具体锚点上，摘完剩下的是一段谁看都像的评语。

### 第二条：每轮请求都在，不是只在第一轮

人格块是**每一轮请求的固定前缀**，不是开场白。第 30 轮的请求里它必须仍然逐字在场，
和第 1 轮一模一样。

**判据**：取一次长对话，把第 1 轮和最后一轮的请求体都存下来，比较人格块部分——
必须完全相同。如果你的实现是“把人格塞进 messages 的第一条，之后让它跟着历史一起
滚动”，那么它迟早会被历史截断策略挤掉，这就是违反。

**违反后坏在哪**：这是最隐蔽的一条，因为前几轮一切正常。人格滑出窗口之后，模型不会
报错，只会慢慢变回一个通用助手——语气先变，然后是称呼，最后连约定都不认了。
用户的体感是“它今天有点怪”，而你在日志里找不到任何异常。

顺带一条反例，是我们自己交的学费：**不要指望 MCP server 的 instructions 承担这件事**。
三轮真机测试的结论是 instructions 只算辅助，很多前端根本不把它递给模型。主动性的
主力必须在人格文件里（见下方坑①）。

### 第三条：每次会话从磁盘重读

每开一次新会话，重新从磁盘读人格文件。不要在进程启动时读一次就缓存到进程死。

**判据**：进程不重启的情况下，改一下磁盘上的人格文件，再开一个新会话——改动必须
立刻生效。生效不了就是违反。

**违反后坏在哪**：这是记忆写回与“升层”的生效通道。用户亲手确认过的更新——改掉一条
说错的事、把一件重要的事升进人格文件——写进了磁盘，却被你缓存的旧版本挡在外面，
悄无声息。用户会以为自己确认的动作没被当回事。

### 第四条：人格块整块连续，你自己的逻辑不穿插进块内

系统提示、工具说明、时间戳、RAG 检索结果、安全提示——这些都不许插进人格块的中间。
人格块从开头到结尾是连续的一整段。

**判据**：请求体里从人格块第一个字到最后一个字之间，不应出现任何非人格文件的内容。

**违反后坏在哪**：顺序即权重、位置是放大器。人格文件本身就是按权重排过序的（开篇
的立场、结尾的最终约定占的是最重的两个位置）；把工具说明穿插进去，等于把不变量
稀释进易变噪音，也把你精心排的顺序打乱。

### 第五条：易变内容放在人格块之后

当前时间、当下状态、工具清单、检索回来的记忆块——这些每轮都在变的内容，一律排在
人格块**后面**。

**判据**：请求体里人格块的**起始偏移量**在每一轮都应当相同（前面只有真正不变的
系统前缀）。偏移量随轮次漂移，说明有易变内容跑到前面去了。

**违反后坏在哪**：前四条定的是正确性，这条定的是成本。人格块是稳定前缀，主流 API
的 prompt cache 都按前缀命中——放在最前面它每轮都能命中缓存；前面塞一个每轮都变的
时间戳，缓存每轮失效，你为同一段内容反复全价付费。

## 四个坑

### 坑① MCP instructions 到不了模型 → 主动性指引写进人格块

很多前端不把 server 的 instructions 递进上下文。所以**“什么时候该查记忆、查什么、
查不到怎么办”这套主动性指引不能只放在 instructions 里，必须进人格文件**。

好消息是这件事架构上早就备好了：人格文件规格里 `retrieval_convention`（检索约定）
是必填字段，初始化流程会自动填上一份被真机验证过的默认措辞。你要做的只是确保
第一条到第四条成立——它在人格文件里，逐字、每轮、整块。

### 坑② 没有“会话结束”事件 → idle 超时 + 自动兜底

`latent_thread_close`（记下这次聊到哪、窗口结束时的状态，并复核未解决清单）在有宿主的客户端里靠
模型自觉调用；自建前端里，会话往往是用户直接关掉标签页，没有任何结束事件。

做法：**用 idle 超时代替结束事件**——最后一轮之后静默超过一段时间（建议 30 分钟起，
按你的产品节奏调）就代表会话结束，这时候由你的前端调一次 `latent_thread_close`。
真漏了也不会断线：服务端有自动兜底，会从最后几轮生成一条收尾，并明确标注
“自动生成、未经确认”，不假装是模型确认过的判断。

窗口极少优雅结束，所以兜底不是可选项，是主路径之一——但兜底质量不如主动收尾，
能调就调。

### 坑③ 纯浏览器前端：起不了子进程，走 HTTP 那条

记忆服务默认是 stdio 子进程形态的 MCP server，纯浏览器里的前端起不了子进程。
**出口是 server 自带的 Streamable HTTP**：`python mcp_server.py --corpus <语料目录>
--http 127.0.0.1:8765 --token <口令>`，前面套一层反代管 TLS。

⚠ **但页面不能直连这个端口，要经你自己的后端中转**，两个理由都是硬的：

- **server 有 Origin 防线**：带 `Origin` 头、且主机名不是 `localhost`／`127.0.0.1`／
  `::1` 的请求一律 403（规格要求的 DNS rebinding 防线——浏览器页面拿本地端口当跳板
  正是它挡的形态）。浏览器发的每个跨源请求都带 `Origin`，所以页面直连必然吃 403。
- **token 不能落进前端代码**：落进去等于把记忆库的钥匙公开发布——`latent_search`
  读全库、`latent_append` 能写入。鉴权必须由你的后端代持。

所以这条路的形态是：页面 → 你的后端 → HTTP MCP。后端那一跳照付三条代价：
**要公网 HTTPS**（域名 + 证书 + 一台常开的机器）、**必须配 token**（绑非回环地址
不配 token，server 直接拒绝起动）、**语料会离开本机**。

### 坑④ 模型异构：四家验通，成色逐格挂账；仍不是一条线

这套主动性指引到目前为止验过的如下。**这张表按厂家挂账：某一格通，只代表那一家
在那一个载体上通，不许借给别家。** 表里写到具体型号的地方，是记"实际跑的是哪个"
（换了型号结论不一定原样成立），不是把这一格的结论收窄到那一个型号。

| 厂家（实测的型号） | 载体 | 验到什么程度 | 结论 |
|---|---|---|---|
| **Claude**（`claude-*`，走 Claude Code） | 有宿主的客户端 | 日常使用 + 新会话验法 | **通** |
| **GPT**（走 Codex） | 有宿主的客户端 | 日常使用 + 新会话验法 | **通** |
| **DeepSeek `deepseek-chat`** | 参考宿主 `src/reference_host.py` | 3 次独立会话，3 次主动查 | **通 3/3** |
| **GLM `glm-5.2`** | 参考宿主 `src/reference_host.py` | 9 次独立会话（三种问法各 3 次），9 次主动查 | **通 9/9** |
| **GLM `glm-4.6`** | 参考宿主 `src/reference_host.py` | 9 次独立会话（同上），9 次主动查 | **通 9/9** |
| **Grok `grok-4.5`** | —— | **还没测** | **未验，不预先声称支持**——这一格不是“服从度差”，是**还没测**，别当成负面结论读 |
| 其它厂家（其它国产模型、开源模型） | —— | 没测过 | **未验，不预先声称支持** |

四家验通说明这套写法不是靠某一家的脾气吃饭，但**它仍然只是四家，不是一条线**。

**GLM 两个型号验到的成色，以及一条它们和 DeepSeek 不一样的地方**：

- 载体、验法、语料结构与 DeepSeek 那次完全一致（同一个参考宿主、同一套三窗口
  合成语料的写法、宿主同样不代调任何工具）；问法扩成三种各 3 次，共 9 次独立会话：
  **具名式**（带专名，如“厨房那台咖啡机上次到底是哪儿坏了”）、**归纳式**
  （不带专名，如“那阵子我都在折腾些什么”“我这个人遇到东西坏了一般是什么反应”）、
  **库里没有的事**（牙医、猫、去年春节——考的是知不知道自己不知道）。
- **检索约定：两个型号 9/9 全过**，每次都是第一句就自己调 `latent_search`，
  没有任何一次直接说“我没有相关记录”或现编。
- **边界话术也跟着生效**：三条“库里没有”的问题，两个型号 6 次全部答的是“我这边
  没找到”“不在我这儿”“记忆库从 2026-05-03 起才有记录”，**没有一次说成“没发生过”**。
  `glm-5.2` 还在归纳式那题上主动标了“这只是我记录里的一次，样本太少，不敢说这就是
  你‘一般’的反应”——比要求的分寸还紧一点。
- **一条如实记下的偏差：`latent_session_start` 的服从度明显低于 `latent_search`。**
  人格文件里“新会话开场先调一次 `latent_session_start`”这条会话约定，`glm-5.2` 9 次里只有
  5 次调了、且**一次都不是调在 `latent_search` 之前**；`glm-4.6` **9 次一次都没调**。
  DeepSeek 那次是“先 `latent_session_start` 再 `latent_search`”。也就是说：**检索约定跨模型
  稳，开场约定不稳**（措辞没有为此改动，见下）。
- 没验到的：**检索质量没验**——语料是为这一测造的三个干净窗口，验的是“主动性带不
  带得起来”，不是“查得准不准”；**这一轮没有验真实产品前端**——载体仍然只是参考宿主。
  后来补到的生产前端证据单列在下方，不能倒借给这一轮。

**措辞没有为任何模型开小灶**：`RETRIEVAL_CONVENTION_FIELD`（那份三轮真机验证过的
检索约定措辞）对所有模型是同一份，没有哪一段是为某一家加强的——两个 GLM 型号在
这份措辞下就是 9/9。`latent_session_start` 那条偏差属于**会话约定**、不属于检索约定，
只观察到两个型号、样本不足以定措辞，所以照实记在上面、不改措辞。

**DeepSeek 那次的成色，说清它验到了什么、没验到什么**：

- 载体是 `src/reference_host.py`——本项目自己那份百来行的参考宿主，
  一个**照契约五条拼请求的自建前端最小形态**，不是任何真实产品前端；
- 宿主**故意不代模型调任何工具**（`latent_session_start` / `latent_search` /
  `latent_thread_close` 前端一个都不替它调），所以“它调了 `latent_search`”这件事
  只可能是模型自己的选择——这正是这一测要看的；
- 三次独立会话（每次一个新进程、新会话），各问一件只有历史记录里才有的事、
  一个工具字眼都没提，**三次都是先调 `latent_session_start` 再调 `latent_search`，
  然后带着查到的细节作答**；
- 顺带验到边界话术也跟着生效：问一件语料里根本没有的事，它答的是“我的记忆里
  没有”“不在我的记忆库里”，而不是“没发生过”——契约要的正是这个分寸。

⚠ **截至 2026.08.02，这组跨模型实验验过的载体只有参考宿主**——GLM 两个型号也是
跑在它上面，换的只是三个环境变量，不是换了一个新的自建前端。这个历史边界继续成立，
但“我方真实产品前端仍然是零个”已经被后续生产证据取代。

**我方真实生产自建前端已补到一例**：这一例属于下节所说的“借宿主引擎”
形态，由 Node 宿主驱动 Claude Code 常驻进程，Latent 走回环 HTTP。判据是协议握手返回
当时五个 `latent_*` 业务工具，真实主聊天主动调用 `latent_search`，并同时命中两段
目标原文；采集条件为 VPS 生产环境、Latent `656a044`、Voyage `voyage-3.5`、182 个
Markdown／869 个切块。2026.08.02 的契约试点还逐条核过人格全本、每轮常驻、哈希重读、
整块连续与易变内容后置，五项均符合且前端无需为契约改代码。⚠ 这只证明这一种宿主形态；
自己直调模型 API、自己拼请求体的前端仍须用本契约逐条自验，不能借这一例的成色。

⚠ **2026.08.05 收到一份外部报告，说清它是什么成色再看**：一位外部使用者在
**他自己的自建闭源前端**（`generic` 档，按本契约自行接线，承载线为 Claude CLI）
上跑通了六步初始化并做了五轮真实对话——**这是外部转述，我们没有复现能力**
（那是他自己的语料和前端），所以**在当时**没有据此把“我方验过的真实产品前端”改成
非零；当前口径的变化来自上面的我方生产证据，不是把这份外部转述冒充复现。
这份报告里唯一跟本节结论直接相关的一条是**再次印证了前面那条偏差**（`latent_session_start`
的服从度明显低于 `latent_search`）：
检索约定被遵守，而“开场调 `latent_session_start`／结束调 `latent_thread_close`”那条会话约定，
五轮下来 `threads.jsonl` 始终没被创建。**方向与我方两次实测一致，措辞照旧不改。**
但它证明的是**照契约拼出来的请求确实能把主动性带起来**，**仍然不替你的实现背书**
——契约第一到第四条在你那儿成立与否，只有你自己 diff 请求体才知道。

自己验很快，一次新会话就够：**开一个全新会话，第一句问一件只有历史记录里才有的事，
别提任何工具字眼。** 接通的标志是模型主动查了记忆再回答，而不是直接说“我没有
相关记录”。没查的话，先照契约第一到第四条自查请求体（绝大多数是人格块没真的
到模型手上），再考虑是模型本身不吃这套。

## 借宿主引擎的自建前端：五条怎么核对

有一类自建前端不自己调模型 API，而是把 Claude Code / Codex 这类**自带人格文件
约定的 CLI 当引擎**驱动（spawn 常驻进程、stdin/stdout 通信）。这个形态下，
四件事由宿主替你做，上面五条判据里"打印请求体""存下第 1 轮和最后一轮""量起始
偏移量"你都执行不了——请求体在宿主手里。你的责任换成三条，每条一样可核对：

1. **人格文件全本交给宿主，你不碰原文**。固定 cwd 指向人格文件所在目录，让宿主
   按它自己的约定加载；不做提取版、精简版、"关键段落版"——那是第一条的违反形态
   换了个位置发生。判据：你的 spawn 参数里不该出现任何"把人格内容作为参数传入"
   的口（`--system-prompt-file` 指向节选文件这类）；有，就说明有一份不是全本的
   副本在流通。
2. **你自己的注入渠道一律不进人格块**。追加提示走宿主的追加口（appended system
   prompt 这类，落在人格块之外）；时间、状态、工具清单这些易变内容拼进**每轮的
   用户消息**里——消息侧天然排在人格块之后，第四、五条就都成立。判据：搜你全部
   代码里往宿主写入的每一条通道，逐条问"它落在请求的哪个位置"。
3. **长命进程要自己造"重读边界"**。常驻进程没有"新会话"这回事，照字面执行
   第三条会退化成"永远不重读"——用户确认过的人格更新永远进不来。做法：定期算
   人格文件哈希，一变就杀进程重生（宿主重生时自然从磁盘重读），对话靠历史重放
   接回。判据：进程不重启的情况下改人格文件，一个同步周期内新回复必须已经带着
   新版本。

验收仍用坑④那一招，一次新会话就够：问一件只有历史记录里才有的事，不提工具字眼。

## 出货之后的第一件事

跑 `--client generic` 会给你三样东西：`persona.md`（人格文件）、这份契约的副本、
`mcp-config.json`（记忆服务的接入参数）。

**注意：generic 档没有宿主替你注入。** 把 `persona.md` 按上面五条拼进你自己的
请求，这一步是你的责任，也是这份文档存在的全部理由。拼完照坑④那个方法验一次接通，
再往下走。
