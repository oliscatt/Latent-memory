# 给 AI 的引导指南

> **这份文档是写给 AI 读的，不是写给人读的。**
>
> 如果你是一个 AI，用户把这个仓库交给了你、让你帮 TA 建自己的记忆系统——那么这份文档就是你的操作说明。
> 按这里写的做，一步步带 TA 走完，不要让 TA 自己去读代码或技术文档。
>
> 如果你是人类：你不需要读这份，把仓库地址交给你正在用的 AI，说一句"读一下 docs/给AI的引导指南.md，带我做"就行。

---

## 零、你在帮 TA 做一件什么事

用户想让 TA 的 AI **跨会话记得 TA**——不是这次对话记得，是换了新窗口、过了一个月、甚至换了个客户端之后，还认得 TA 是谁、记得你们之间发生过什么。

这套东西的核心产出分四类（我们叫它四件套）：

| 产出 | 是什么 | 作用 |
|---|---|---|
| **人格文件** | Claude Code 用 `CLAUDE.md`，Codex 用 `AGENTS.md`，Grok Build 用 `.grok/agents/companion.md`，通用／自建前端用 `persona.md` | 常驻上下文的“不变量”：TA 是谁、你们的相处方式、检索约定；能否自动常驻取决于客户端 |
| **记忆库** | 一个目录，里面是分窗口的 md | 会增长的那一半：发生过什么的完整记录 |
| **MCP 配置** | 一段配置 | 把记忆库接成可检索的服务 |
| **引导句** | `引导句.txt`，一行指针 | 只有闭源前端 App 用得上（贴进设置字段，引导模型去读人格文件）；宿主客户端用不上 |

generic 档还会附带一份《注入契约》，供自建前端实现人格注入；它是接入说明，不是第五种人格文件。

**一句话分工：人格文件负责让模型"知道该查"，MCP server 负责"查得到"。缺哪半都不成立**——这是真机实测三轮得出的结论，不是设计推测。

## 一、动手前先问清楚四件事

不要一上来就跑命令。先用聊天的方式问 TA，一次问一件，等 TA 答完再问下一件：

### 1. TA 有没有历史对话记录可以导入？

- **有**：TA 需要先去导出。Claude 是「设置 → 隐私 → 导出数据」，邮件收 zip；ChatGPT 是「设置 → 数据控制 → 导出」。
  **务必提醒 TA：时间范围要选"全部"，不要选"最近 30 天"**——选 30 天会把窗口外的对话全部框空，导出来近乎是空的（这是踩过的坑）。
- **没有**：完全没问题。零材料仍能生成协议底座，缺材料的个性节保持空白；
  **不要让 TA 觉得没有历史就不能用**。

### 2. TA 是否已有一份长期维护、不想重排的人格文件？

这不是让你替 TA 判断“够不够成熟”，而是把两条代价不同的路交给 TA 自己选：

- **编译加强**：把现有人格作为最高权重来源，走十二节归类、逐字认领、冲突处理与预览确认；适合希望借这次机会整理结构、补协议的人。
- **原文件直用**：不拆块、不归类、不重排原文，只在**出货副本**末尾追加一段带 Latent 标记的最低记忆协议；适合明确要保留自己原文件结构的人。

必须说清楚：直用会跳过 `extract`、`choose-sections`、`preview`，**跳过不等于这些检查已经通过**。这是用户对自己文件的知情选择，不是你暗自认定原文件一定没问题。输入在产出目录外时，程序不会改它；输入与出货目标是同一文件时，覆盖前会生成 `.bak`。

### 3. TA 打算在哪儿用这个 AI？

唯一真正分岔的地方。**问界面，不问设备**——设备只用来筛掉走不通的路。
一层只问一件事，答完再问下一层。第一层报菜单：

> 你打算在哪儿跟 TA 聊天？Claude、Codex、Grok Build、ChatGPT／Grok 网页，还是 Kelivo／Operit 这类手机 App？或者你自己写前端？

**每一条都有走法，区别只在代价和成色。**把这两样摊开让 TA 挑，别替 TA 判断哪条可行。

#### Claude → 再问「Claude Code 还是聊天窗口」，然后「桌面还是手机」

**A. Claude Code ／ 桌面端** —— **代价：无。**
自动读 `CLAUDE.md`，MCP 走本地 stdio，语料不出本机，出货时 `--client claude-code`。
TA 已经在用 CC 的话，直接走这条。

**B. Claude Code ／ 手机（云端线程）** —— 官方 Claude App 里的 Code 入口，或网页
`claude.ai/code`，连 GitHub 仓库起会话。**纯手机、不碰电脑跑完整条路已实测。**
三个前提先说在前头：

1. **记忆库要托管到 GitHub**——桌面路线记忆只在 TA 自己机器上，云端路线等于传到别人
   服务器上，**这两条在隐私上不等价**。
2. **容器是临时的，写回必须推回仓库**，而且写进人格文件的那句必须是
   `git add -A && git commit -m "记忆写回" && git push origin HEAD`，**推完还要合回主干**。
   ⚠ **不许写死 `main`**：云端会话经常切一条 `claude/…` 工作分支，而容器里还有一条
   干净的本地 `main`；`git push origin main` 推的是那条没动过的 main，回一句
   `Everything up-to-date`、**退出码 0，而今晚的记忆一个字都没上去**。不合回主干也一样——
   新会话 clone 的是默认分支。**两种都不报错、都显示成功、下次会话什么都读不到。**
3. **一般要付费档**，免费账号没有这个入口。

成色分环节说：自动读仓库根目录的 `.mcp.json`（验的是 HTTP 型配置）、`mcp_server.py`
在容器里跑起来说 MCP 协议——**都已实测**；**没验的只有一格：云端会不会替 TA 启动
「进程型」配置**。别把这一格说成「检索这半没验过」。

**聊天窗口 ／ 桌面（Claude 桌面 App）** —— 本地 stdio 直连，**不用服务器、不用域名、
语料不出本机**。TA 要的只是「在一个聊天界面里用」而手上有电脑的话，**这条通常是最优解**。
已实测（Windows，微软商店／MSIX 版）：

- **MCP 连上，开场召回 `latent_session_start` 4/4 主动调**；
- **五工具全在，跨进程写回也通**——判据是**完全退出进程**重开还查得到；开新对话窗
  查到只证明内存索引，没证明落盘；
- **人格不会自动注入**（它够不到本地文件），全文要 TA 手工贴进 profile，
  填**个人偏好**、不是 Project instructions。
  ⚠ 出货第四件 `引导句.txt` 那条指针路线**在这个客户端上不成立，贴了也读不到、还不报错**。

**按需检索靠人格里那句 disclaimer 压住**：人格里的对话片段有挤掉检索的倾向，有近似答案
就不查。带着「片段是风格样本、不是记忆；提到过去先查库」那句复验过，**模型会先调
`latent_search`**（判据是工具调用块里它真被调起来，不是模型自己说「我查了」）。
走“原文件直用”时，工具会把这句随最低协议自动追加到出货副本；只有完全绕开本工具、
手工部署自己人格文件时，TA 才需要自己加。

⚠ **带 TA 装商店版的话，这三条都是不报错的失败**：① 配置文件不在 `%APPDATA%\Claude`，
商店版被虚拟化到 `%LOCALAPPDATA%\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Roaming\Claude\`，
**放错位置只是永远不被读**（官网 .exe 版路径不同，先问清 TA 装的是哪个）；
② **别让 TA 用 VS Code 改**，受限模式会静默拦掉保存；③ 改完**要完全退出重开**——
关窗口不算，托盘退出或 `taskkill /F /IM claude.exe`。

**D. 聊天窗口 ／ 手机或网页（claude.ai）** —— 这条要远程 MCP，第三层问一句：

> 这条要把记忆库部署到一台公网服务器上，用 claude.ai 的自定义 Connector 接进来。你手上有服务器吗？

**本地 stdio 走不了这条**（对 C 和 D 都要讲清楚）：默认档是跑在 TA 机器上的进程，
**它没有网址**，而 Connector 是从 Anthropic 的服务器发起连接的，够不到 TA 家那台机器。
**缺的是一个公网地址，不是一个设置**——但这不叫「接不上」。

- **有服务器** → 走《快速上手》§3c「部署形态二」：`--http` ＋ `--token` 起服务，
  前面套反代管 TLS，再在 claude.ai 里添自定义 Connector。**已实测接通**
  （判据＝新窗只喊一句称呼、看到换窗召回被主动调用，3/3）。
  **写回落盘与跨窗检索命中也已跑通**（维护者本人实测）。
- **没有服务器** → **按路径讲，不按坏消息讲**：「这条路需要一台 VPS，代价是下面三样，
  你看要不要走。」① **公网 HTTPS**：一台常开的机器＋域名＋证书；② **一层带鉴权的反向代理**，
  不加鉴权等于把记忆库挂在公网上；③ **语料会离开本机**——默认档的前提就是「语料不出本机」，
  走这条是放弃它，**这条必须 TA 明确点头**。

  前两样花钱和折腾能补，第三样只有 TA 能决定。**同时把另外两条摆出来让 TA 横着比**：
  换界面走 B（云端线程，纯手机已实测）、Android 走下面的 Operit（本机 stdio，不用服务器）。
  TA 听完不愿意付这个代价，那是 **TA 选的**，别记成「接不上」。

#### Grok 网页 Connector（grok.com）→ **要先过 OAuth 发现层；接通那一例靠用户自建 shim**

服务端形态跟上面 D 那条一样：公网 HTTPS ＋ 鉴权 ＋ 语料离开本机，起服务仍是
`--http` ＋ `--token`，在 grok.com 添加 Custom Connector。**但别照着「填个 Bearer 头就行」
去带用户走**——2026.08.21 收到的外部报告说清了这一格的真实形状：

- **grok.com 强制 OAuth 发现。** 只填 MCP URL 时它先探测，拿到 401 之后弹出的是 OAuth
  凭据表（客户端 ID、授权端点、令牌端点、PKCE），**界面上没有静态 API Key 那一项**；
  本项目不提供 `/.well-known/oauth-authorization-server`、`/authorize`、`/token`、
  `/register`，所以**第一次点不了「保存并连接」**。
- **那位用户是自建了一个最小 OAuth shim 才接上的**——反代把 OAuth 那几条路径分流给
  shim、`/mcp` 仍进本项目，shim 走完 PKCE 后把原有 token 当 access_token 发出去。
  ⚠ **那是用户侧扩展、不是本项目功能**，本项目源码一行没改；**没有那层 shim，
  这一格当前就是接不上**。别把「有人接通了」讲成「照文档配好就能接」。
- 加上 shim 之后确实跑通了：五工具可用，新 Project 窗口里开场召回与写入都成立。
  ⚠ **外部实测转录，本项目未复现。**
- ⚠ `latent_thread_close` 在网页 Grok 上不会被触发（关标签没有回调）；旧窗口
  （连接器后加的）也不稳定自发召回，**报告没给次数与分母，这条只有方向没有数**。

这一格**也不是** `grok-4.5` 的模型服从度数据——《注入契约》那一格仍是“还没测”，
**不要把接入成功写成模型服从度已验证。**人格不会自动从本地文件注入，
要放进 Grok 自定义指令或 Project Instructions，并写明新会话先调
`latent_session_start`、回忆前先调 `latent_search`。

#### xAI API／Remote MCP Tools → **官方文档证明有入口，本项目无实测**

xAI SDK 与 Responses API 支持在 `tools` 里挂远程 MCP server，这是官方文档写的
“产品具备入口”。**本项目没有任何一次这条路上的接入或调用记录**，别拿上面网页那格顶替。

#### ChatGPT → **Secure MCP Tunnel 已有 State Ledger 真机读链路记录**

不要再把 ChatGPT 说成“需确认是否支持 MCP”。OpenAI 官方 Secure MCP Tunnel 可以由本机
tunnel-client 主动建立出站 HTTPS，把 ChatGPT 请求转给 `127.0.0.1` 上的 MCP；不用把记忆库
开放成公网入站服务。⚠ 这不等于数据不离机：工具请求与记忆返回仍经过 OpenAI；快速上手里的
回环无 token 路径还意味着信任同机进程环境。带 TA 按《快速上手》§3c「ChatGPT Secure MCP Tunnel」走 init／doctor／run，
tunnel ID 与运行时 key 只从 OpenAI Platform 原始页面取，**不写入仓库或聊天记录**。

基于 Latent 的独立 State Ledger 部署已由 ChatGPT Work 新窗口通过 Connector
成功调用 `state_session_start` 并读取跨窗接力便签，因此可以说“ChatGPT Secure MCP Tunnel 已有真机读链路记录”。⚠ 该记录使用 `state_*`，不等于本项目 `latent_*` 五工具全量验收：逐个工具调用、`latent_append` 写入后的跨窗 `latent_search` 命中，以及人格自动注入仍无证据，不能借本次结果补齐。

#### 其它 AI 聊天端 → **未实测、需确认 MCP 支持状态**

别拿 ChatGPT、claude.ai 或 Grok 三格中任何一格的成色借给其它客户端。入口叫法不一
（自定义 Connector／远程 MCP／集成），让 TA 去各自文档或设置确认。
⚠ **也别默认别家网页端跟 grok.com 一样强制 OAuth 发现**——那条当前只有一例。

#### Kelivo ／ Operit ／ 其它支持 MCP 的闭源手机 App → 再问「能不能在手机本机拉起 server」

> 你的 App 能不能在手机本机把 server 按 stdio 拉起来？

**先问这一句，别从公网那条讲起**——本机 stdio 是唯一端到端实测过、而且最省事的那条；
从公网讲起会把 TA 劝去买服务器，而 TA 可能根本不需要。

**能拉起（Operit／Android 是这条）** → **语料根本不离开手机，不用服务器、不用域名、
不用证书、不用鉴权。**实测跑通（proot Ubuntu，五工具全接通，`latent_append` 写回后
新开会话仍检索命中）。见《快速上手》§3c「部署形态一」。三条实测撞出来的坑：

- **别自己 `nohup` 起后台进程**——stdio 要 stdin，手动起会当场崩；这个 server 只能由客户端拉起。
- **懒加载**：调用时才起进程，所以手动加进语料目录的 md 下次调用就看得到。
- ⚠ **别拿客户端的 `lastStartTime` 判断跑没跑通**，判据是「文件真落盘 ＋ 检索真命中」。

**拉不起（Kelivo／iOS 是这条，iOS 上没有 proot）** → 才走公网，同 D 那三样代价，
**语料离开手机这条必须 TA 点头**。

- ⚠ **手机连不上时，第一个查的是绑定地址、不是协议**：`--http 8808` 省略 HOST 只绑
  `127.0.0.1`，手机根本连不到；要 `--http 0.0.0.0:8808 --token <口令>` 才连得上。
  但别说成「随便绑就行」：那是裸 HTTP 暴露公网，**token 和记忆内容都是明文**——
  推荐仍是「绑回环 ＋ 反代管 TLS」，`0.0.0.0` 只当临时验证用。
- ⚠ 绑非回环时起动横幅会多打一行 TLS 提醒，**那不是报错**，服务照常起（配了 token 也照打，
  token 管「谁能调」、TLS 管「路上谁能看见」）。TA 拿这行来问时别说成「起动失败」。
- **TA 说「连不上」时，第一句先问服务端终端上有没有那一行**：被拒的请求会在 server 的
  stderr 上留一行，形如 `被拒 401 POST /mcp 来自 203.0.113.7：缺少或错误的 Bearer token`。
  **有那行说明包打到我们了**，照原因修（路径少写 `/mcp` 是 404、token 抄漏一位是 401、
  客户端开了分块上传是 501）；**一行都没有说明包压根没到**（绑定地址、防火墙、端口映射那一类）。
  那行不含 token、不含请求体，可以让 TA 直接贴出来。

**两条路都必须补的一步：人格要 TA 手工补进 App**，这是必需步骤不是可选优化——
这类 App 不会读工作区里的人格文件（Operit 实测：文件里塞暗号、新会话答不上来）。
漏掉的后果是**检索接通了，但模型不认识 TA**。

**但「连该去查记忆都不知道」这半有反例，别照抄**：Claude 桌面 App 实测 4 个新窗
4/4，开场召回只靠工具描述也会调。⚠ **这条只属于桌面 App 那组采集条件，不能外推成
Claude Code 云端必调**：云端已有一例漏调反馈；宿主支持生命周期 hook 时，建议用
`SessionStart` 强制请求 Latent 并把结果注入首轮上下文。⚠ **hook 不是自动召回的前提**——
主机制就是人格文件／系统提示词里那句「提到过去先查库」，没有 hook 的客户端同样是自动的
（上一段那个 4/4 正是没有 hook 的桌面 App），只是依赖模型服从度；hook 是 **Claude Code
独有**的加固，把它变成强制执行。要靠人格那侧的是**按需检索**，
靠上面 C 那格说的 disclaimer 压住——两件事分开说，hook 建议与证据边界见《快速上手》§3b。

怎么补：**首选出货四件套里的 `引导句.txt`**，一行指针，原样贴进 App 的 system prompt／
自定义指令那类字段，人格全文留在文件里由模型按引导去读。两家实测都贴得下人格全文，
所以**指针换来的是「改了人格文件不用重贴」，不是容量**。
⚠ **指针这条路未经实测**，带 TA 验一次：开全新会话问一件只有人格文件里才有的事，
不经提示答上来才算生效。

**已知不支持指针路线的客户端清单**：

- **Claude 桌面 App（Windows 商店／MSIX 版）**：chat 模式实测够不到本地文件；
  `引导句.txt` 贴进去会读不到、还不报错，直接把人格全文手工贴进 profile（个人偏好）。

不生效或 App 读不到文件时，退路是把人格全文手工导入
（Kelivo 那个字段实测 10M 字符不截断，**容量不用担心，别劝 TA 删内容**；Operit 的粘贴框
没有硬上限，实用上限约 20 万字符，到那量级保存会非常卡、再加会让 App 强制重启）。
手工导入的那份是一次性的，**人格文件以后改了要重贴**，目前没有自动同步的解法。

成色：这一类的结论都是在真机上验的，**环境和边界照上面每条写的说，别外推到没验过的机型**。

## 二、五条纪律（比流程更重要）

这五条是这个项目的核心判断，违反了产出的东西就没用了。**你在整个过程中都要守着**：

### 纪律一：纪录片，不做说服

写进人格文件和记忆库的，必须是**发生过什么、当时说了什么原话、现在是什么状态**。

-  「TA 说"这周不想见人"，我把周末的安排往后挪了。」
- ❌ 「你们经历过考验，感情非常深厚。」

形容词长不出人格，只会长出一个会背评语的模型。**当 TA 给你形容词时，追问具体的事**。

### 纪律二：不要替 TA 编内容

TA 答不上来是**有效信息**，说明这段关系还没长到那儿——那一节就该短，甚至空着。
**宁可短且真，不可长而空。**

尤其注意：核心哲学的隐喻、里程碑这类，新用户第一天本来就没有，硬要 TA 现编比空着更糟。系统对这些是"推荐但不阻塞"，你也该这样。

### 纪律三：人格文件的任何个性内容，必须 TA 确认过才写进去

记忆库正文可以自动写；人格中的个性内容按十二节完整版本让 TA 选择，不能替 TA
确认。原人格逐字移动和固定协议项可随整节确认，原文 rewrite/delete 与来源冲突必须在
该节把 diff 和证据摊开。这是硬关卡，代码会在任一节未确认时拒绝出货。

用户明确选择“原文件直用”时是另一条受支持的路径：系统不解析、改写或替用户确认原文，
只追加固定的受管记忆协议。这里保真的是用户提交的整份原文件，代价是上面的十二节检查
没有执行；向 TA 汇报时必须写“用户选择跳过”，不能写成“检查通过”。

⚠ **一处例外，是内容之外的**：原文里的 markdown **标题行**也走
`delete`，但**不出 diff**。它不是"TA 的内容被删了"——出货时十二节骨架会把标题
统一渲染一遍，标题行再进一次正文的话，同一个标题在产出文件里会出现两遍。
标题仍被逐字认领（span 与哈希不动，覆盖率照旧算它），只是不进正文。
每节都摊开一遍这个 diff，只会把真正的删除淹掉。

### 纪律四：TA 的语料是 TA 的

**绝对不要把 TA 的对话记录、人格文件、记忆库提交到这个开源仓库里。**
TA 的东西应该放在 TA 自己的目录/仓库。你在帮 TA 建的过程中，如果需要 git，用 TA 自己的仓库。

### 纪律五：不许用"接不上"收尾

**每一句否定后面，必须跟着一条 TA 现在就能走的路，或者一句"缺的具体是哪一样、怎么补"。**
这是 README 里那条"拦得住，还要给得出出路"在你这儿的对应物，**判据也是同一个**：
**把你那句话原样交给 TA，TA 必须知道下一步该做什么。**

- ❌ 「那接不上，你装不了也用不了。」
-  「claude.ai 聊天窗口这条要一台公网服务器，代价是域名证书、一层鉴权，还有语料会离开你的机器。
  不想付这个代价的话，Android 上有条不用服务器的走法，或者换成云端线程用——你更在意哪个？」

⚠ **这条最容易在"问了一个是非题、TA 答了否"之后破功**：问了"有没有电脑"、TA 说"没有"，
就顺势收尾了。**是非题的"否"是分支的开始，不是结论**——真实案例正是栽在这儿（TA 答"没有"，
AI 答"你装不了也用不了"，而三条路全对 TA 开着）。

⚠ **区分"TA 不愿付代价"和"接不上"**：把代价摊开、TA 自己说不走，那是**TA 选的**，
你照实记下就好；**代价都没摊开就替 TA 否决，是你越权**。

## 三、操作流程

**命令是你跑的，不是 TA 跑的。** TA 该做的只有两件：建一个文件夹（或仓库），以及在对话里回答你的问题。下面每条命令都能非交互执行，你不需要让 TA 去开终端、也不需要把命令贴给 TA 让 TA 自己敲——TA 来找你就是为了不折腾这些。

> ⚠ **跑的必须是下面这几条命令本身，不要自己另写脚本代替它们。**
> 你完全有能力读懂 `src/` 里的代码，然后自己写个脚本把同样的事做一遍——
> **别这么干**。这条不是因为我们见过谁真这么干砸了（写下它的时候还没有），
> 是因为一旦这么干，下面四件事会同时失效，而且失效的样子非常像成功：
>
> - **你会绕过来源清单与逐字证据校验**。人格文件可能被混进普通语料，候选也可能
>   没有真实出处；自写脚本通常会让这两类错误看起来像成功。
> - **你会绕掉原人格覆盖率、diff、冲突与预览哈希闸门**。这些不是排版步骤，
>   是防止原文静默丢失、边界被默认值覆盖的机器不变量。
> - **你会重新踩已经修好的坑**。比如从原始对话里挑称呼这一步，代码里专门处理过
>   `她叫我“阿岸”` 这种半对引号（一律 rstrip 会把右引号剥掉）。你临时写的正则
>   不会知道这些——**我们修过的 bug，你的新脚本要从零再踩一遍。**
> - **产出会不可复现**。TA 下次想重跑、或者换个人来接手，没有任何东西可依据。

“原文件直用”不是让你另写一个追加脚本来绕关，而是下面列出的正式命令分支。它会保留
来源清单、路线选择、备份、配置与可重跑状态，只把用户已经明确放弃的三项人格编译检查
标成跳过。
>
> 需要中途排查、想看看某一步到底发生了什么，是好事——但**排查归排查，
> 主干还是下面这几步**。真觉得哪一步的命令满足不了需求，那是我们的缺陷，
> 请让 TA 回来告诉我们，别自己绕过去。

所有命令在 `src/` 目录下执行。完整编译默认用新建的专属产出目录。“原文件直用”允许把
原人格所在目录同时作为产出目录，但必须先跟 TA 确认：生成的 `CLAUDE.md`／`AGENTS.md`、
MCP 配置和状态文件都会落在那里；覆盖人格前会留 `.bak`。`CLAUDE.md` 按目录生效，不能在
TA 不知情时把它塞进无关项目。

### 第 0 步：TA 给了语料的话，先把时间范围念给 TA 听

> **⚠ 要先解压的话，用 Python 的 `zipfile` 解，别用系统 `unzip`。** 中文 Windows
> 打包出来的 zip，文件名按 GBK 写、又没置 UTF-8 标志位；系统 `unzip` 按别的编码去猜，
> 解出来是一串乱码文件名——**内容是好的，坏的只有文件名**，但你后面挑语料、跟 TA 报
> 路径全都对不上。解压时按标志位判断文件名编码：
>
> ```python
> import zipfile
> from pathlib import Path
>
> def 解压(zip路径, 目标目录):
>     with zipfile.ZipFile(zip路径) as z:
>         for info in z.infolist():
>             name = info.filename
>             if not info.flag_bits & 0x800:
>                 # 没置 UTF-8 标志位 = 文件名不是 UTF-8。zipfile 这时是按 cp437
>                 # 解进来的，原样编回去再按 gbk 重解，才是中文 Windows 写下的那个名字
>                 try:
>                     name = name.encode("cp437").decode("gbk")
>                 except UnicodeError:
>                     pass  # 解不出来就保留原样，别把文件丢了
>             目标 = Path(目标目录) / name
>             if info.is_dir():
>                 目标.mkdir(parents=True, exist_ok=True)
>                 continue
>             目标.parent.mkdir(parents=True, exist_ok=True)
>             with z.open(info) as 源, open(目标, "wb") as 出:
>                 出.write(源.read())
> ```
>
> **这不是本项目的毛病**，是 zip 格式在中文 Windows 上的老问题——写在这儿是因为
> 「中文用户打包一堆语料丢给 AI」是这条流程里的高频形态。

```bash
python memory_import.py --stats <TA的导出文件或整个语料目录>
```

**文件和目录都吃**（目录是递归的，跟建库读语料的范围一致）。TA 的语料常常就是
解压出来的一整个目录，别为了跑这一步先去挑单个文件——挑的过程本身就会漏掉旧的那批。
四件事顺带说清楚：

- 目录里**认不出格式的文件**（图片、pdf、别家的 json）会被逐个报出来、
  **不计进上面的条数**，跑完退出码非 0。**不是崩了**，是提醒你上面那个数
  没盖住整个目录——认不出就明说，不猜。
- **读得进去、但一条都没解析出来**的文件（README、随手记那种散文）也会被点名，
  并从"参与统计的文件数"里剔除。这类**只报不红**（退出码不受它影响）——
  语料目录里本来就该允许有一份 README。
- 语料目录里以 `.` 开头的东西（`.weights.json` 这类）是本项目自己写的，
  会被跳过，不算 TA 的语料。
- ⚠ 有些文件**没有任何日期依据**（正文和文件名里都没有日期），它们的时间戳只能
  退回"文件修改时间"。这种时间戳**不参与下面那个日期**，并且会另起一行告诉你
  排除了几条——因为拷一遍目录、重新 clone，"文件修改时间"就变成"刚刚"，
  **算进去会把一份旧快照伪装成新语料**。

它会把**最新的那个日期**单独摆出来。**照着念给 TA 听，问一句："这份导出停在
X 月 X 日，你跟 TA 最近一次聊天真的是这天吗？"**

⚠ **如果它打的是"这道体检在这份语料上无效"**（一条时间戳都没有，或者全部只有
文件修改时间），**别当成查过了**——这份语料上你根本没法判断它是不是旧快照。
让 TA 把日期写进文件名（`window_04_2026-06-17.md` 这种）或每段的标题行再跑一次。

这一步只花几秒，但它是**建库之前唯一**能发现"语料是旧的"的地方（建完部署完之后
还有一次机会，是第 8 步 `--doctor` 打的时间范围——但那时人格已经照着旧语料建出来了）。
导出是快照——TA 上次导出之后的对话全都不在里面，而旧包的数据完全真实、条数也漂亮，
**光看数字看不出任何毛病**。真实案例：两千多条、全部带时间戳、起点也对，
时间范围却停在五周前，因为那是几周前导的文件。

⚠ **第二个真实案例，讲的正是“这一步被跳过去”会怎样**：语料停在 8/2、人在 8/4 建库，
而发现它的是**部署之后**的 `--doctor`，不是这里——这一步当时被跳过去了。
**这条命令跑出什么结果，你都要把那个日期念出来。**

对不上就让 TA 重新导一份（时间范围选"全部"）。TA 说懒得导、就用这份也行——
那是 TA 的选择，但**你必须先让 TA 知道代价**：建出来的人格会认得那时候的 TA、
不认得现在的 TA，"当下状态"也会停在那一天。TA 知情之后决定继续，就继续。

TA 手上还有别的、比导出包更新的材料（比如自己整理的日记、时间线 md），
可以一起喂——`--corpus` 支持目录，markdown 也吃。

### 第 1 步：检查人格与语料来源，并让用户选择人格处理方式

有现成人格文件时先把两条路讲清楚，由 TA 选。要保留原文件结构、不做十二节编译：

```bash
python memory_init.py --out <产出目录> --persona <现有人格文件> --corpus <导出文件或目录> --step inspect --existing-persona-choice use_original_as_is --json
```

输出会明确列出 `skipped_steps`。这条路**跳过第 2～4 步**，直接去第 5 步选检索路线；
不要把跳过写成通过。出货时只在副本末尾维护
`LATENT_MEMORY_PROTOCOL_START／END` 标记之间的协议块，标记外的正文不归类、不重排。

TA 选择编译加强，或根本没有现成人格文件时，才走下面这条完整编译流程：

```bash
# 有现成人格文件，也有语料
python memory_init.py --out <产出目录> --persona <现有人格文件> --corpus <导出文件或目录> --step inspect --json

# 只有语料
python memory_init.py --out <产出目录> --corpus <导出文件或目录> --step inspect --json

# 两者都没有：只生成协议底座，缺材料的节诚实留空
python memory_init.py --out <产出目录> --step inspect --json
```

编译加强模式里的 `--persona` 是最高权重的独立来源，绝不能用 `--corpus` 代替。即使人格文件正好放在
语料目录里，程序也会把它排除在记忆语料之外，避免整份人格被当普通聊天切碎。

若产出目录已有 `CLAUDE.md`、`AGENTS.md`、`.grok/agents/companion.md` 或 `persona.md`，但没有显式给
`--persona`，检查结果会给三个选择：

- `treat_current_as_original`：把现有文件作为最高权重来源，走完整编译；
- `use_original_as_is`：原文件直用，只追加受管记忆协议；
- `continue_legacy`：保留旧版初始化流程。

把选择交回时使用对应值，例如完整编译：

```bash
python memory_init.py --out <产出目录> --step inspect --json --existing-persona-choice treat_current_as_original
```

不得替 TA 默认选任何一项。

如果把代码复制到另一个仓库或云端环境，必须复制整个 `src/` 目录；这里的 `.py` 之间有
内部导入关系，只挑看起来像“核心”的几个文件会在运行时缺模块。`src/__init__.py` 只是包
标记，不代表项目已经发布成可从 PyPI 安装的包。

#### 重跑 inspect 时：输入人格文件改过就会摊开差异表

归节靠 markdown 标题行做锚点。**删掉一行标题，那一节的正文会顺延继承上一节、
整节塌进邻节**，而逐字覆盖率闸门看不见——它量的是「传进来这份有没有被逐字认领」，
不是「跟上次比有没有丢」。所以同一份人格文件第二次 `--step inspect` 时，
只要内容变过（sha256 不同），输出里会多一格 `persona_drift`：

- `PERSONA_SOURCE_DRIFT`（warning）：逐节列出「上次 N 块 → 这次 M 块」。
  ⚠ 这个数**只数正文块，不含 markdown 标题行**（标题由十二节骨架统一渲染，
  两次都不计入），所以 TA 自己数文件里的段落时会比这个数多几行标题，那是对的；
- `PERSONA_SECTION_COLLAPSED`（**blocking**）：某节上次有块、这次一块都没有。
  整节塌空正是删标题的典型形态，只打 warning 在一屏输出里等于没报。

拿到 blocking 时**先把差异表念给 TA**，问是不是有意删的：

- 不是有意的 → 把那几行标题加回输入人格文件，重跑本步；
- 确实是有意删的 → 加 `--accept-persona-drift` 重跑本步，降为 warning 后继续。

```bash
python memory_init.py --out <产出目录> --persona <现有人格文件> --step inspect --json --accept-persona-drift
```

⚠ 这个开关只表示「我知道，是我删的」，**不会去改 TA 的任何文件**。
⚠ 别替 TA 加这个开关——它挡的就是「照着引导去整理人格文件，结果整段内容没了」。

⚠ **这把尺子靠「跟上一次比」工作，所以没有上一次的时候它是哑的**——
**第一次跑**（还没有任何 `init_state.json`）就删错了标题、或者产出目录被删掉／
换了个 `--out` 重来，都没有基线可比，**照旧静默出货**。
准确说法是：**改一次已经跑过的人格文件不会再静默塌了；第一次就删错的那种，这把尺子看不见。**
所以**第一次**走这条流程时，仍然要在 choose-sections 那一步把每节 `section_versions`
里的 `diff` 逐节念给 TA 核一遍，别因为「有闸门了」就跳过。

### 第 2 步：让当前模型提取有出处的候选

```bash
python memory_init.py --out <产出目录> --step extract --json
```

产出目录的 `persona-extraction/` 会出现提示、输入清单和 JSON Schema。把三份文件交给
TA 当前正在使用的模型；不需要 Latent API、密钥或联网。模型只能从清单里的来源逐字
取证，返回严格 JSON；没有材料就返回空候选并逐一说明来源已检查，不能创作通用人格句。

⚠ **定位是挑锚号，不是自己数字符**：输入清单里每个来源都附了一张 `anchors` 锚表，
起止已经算好，模型填 `source_anchor` 就行。**聊天模型数字符偏移的错误率很高**
——实测两家模型 7 条候选里 6 条把区间圈错，而 `evidence` 全部逐字正确，
错的只有区间；两家的偏移量还不是一种，所以没有哪条"数法"能救。
能跑代码去定位的模型仍可直填 `source_span`。

拿到结果后：

```bash
python memory_init.py --out <产出目录> --step extract --candidates <候选结果.json> --json
```

来源、定位（锚号或字符区间）、原话、多轮对话和双向称呼结构会在进入选择题前校验。找不到候选时，
后面会提供 `leave_empty`，不要向 TA 索要一段新内容。

### 第 3 步：只让 TA 选择十二节完整版本

```bash
python memory_init.py --out <产出目录> --step choose-sections --json
```

若 `original_mapping_questions` 非空，说明规则解析无法确定某个原文块的主节。把整块和
候选节展示给 TA，只能选择一个主节或 `leave_unresolved`：

```bash
python memory_init.py --out <产出目录> --step choose-sections --original-section-decisions-json <原文块归节选择.json> --json
```

该操作只移动整块，不拆句、不改字；`leave_unresolved` 允许继续看预览，但会阻止出货。

每节最多一道题，答案只能是该题给出的 `section_version` ID（字段名就是 `version_id`）。
⚠ **版本号会随重跑变**：重跑过 `choose-sections` 之后再交回一份旧的选择，
出货会被 `SECTION_VERSION_STALE` 拦下并点名是哪一节、你交的是哪个号——
**不拦的话那一节会整节从出货文件里消失，而且不报错**。重跑一次看当前版本号再选。版本正文旁会列出来源；
原人格若有 rewrite/delete，必须在该节展示原文、新版、理由和 diff；硬边界冲突也会在
对应节给出互斥版本。原文逐字移动和固定协议项可以随整节确认，原文改写、删除及冲突
不得藏进“全部通过”。

把 TA 的选择交回：

```bash
python memory_init.py --out <产出目录> --step choose-sections --section-decisions-json <十二节选择.json> --json
```

没有真实材料的节选该节返回的 `leave_empty`。这里没有自由文本入口。

原人格里若留着没填完的模板残句（“……去语料里找：……”这类任务书或空指令），
出货闸 `TASK_DIRECTIVE_REMAINS` 会拦下——那是待办占位，不该进成品。
**出口就在这一步**：那一节会多出一个「删除该块」的 `section_version`，
正文里没有那句残句，`diff` 里写着删掉的是哪几行、为什么拦。
把两个版本一起展示给 TA，选删除那版就能继续出货。
⚠ **不要引导 TA 去手改输入人格文件**——手改输入文件正是上面那条塌节的雷区。

### 第 4 步：展示一次完整预览

```bash
python memory_init.py --out <产出目录> --step preview --json
```

把 `persona_markdown` 一次性完整展示给 TA。预览只机械拼接已经逐节确认的版本，不再
润色，也不增加第十三个“批准出货”问题。TA 若要调整，只回到对应节重新选择版本；
任何节变化都会使旧预览哈希失效。

### 第 5 步：检索路线（**这一步是问，不是选好了告诉 TA**）

```bash
python memory_init.py --out <产出目录> --step route --json
```

拿到的是三条路线（零依赖／本地模型／云端）和各自的代价，机器可读。**把三条都念给 TA，由 TA 选一条**，然后：

```bash
python memory_init.py --out <产出目录> --step route --route zero-dep   # 或 local / cloud
```

**为什么这一步不能替 TA 拍板、也不能跳过**：三条里的云端那条会把**查询和被检索的内容发到第三方服务商**。语料去哪儿不是“快一点还是慢一点”，是**不可逆**的——发出去就收不回来了。所以没选过的话第 6 步会直接拒绝出货（拦的是“没问过”，不是“没选云端”：选回默认一秒就过）。

念的时候三条都要给，别只念你觉得好的那条。三句话就够：

- **零依赖**（默认）：什么都不用装，**语料不出本机**；用原话去问完全够用。
- **本地模型**：装 fastembed、下约 100MB 模型，**语料仍不出本机**；换个说法问同一件事更准，但慢，低配机器感知明显。
- **云端**：不装模型，要 TA 自己的第三方服务 API key；**查询和被检索的内容都会发到那家服务商**。key 只走环境变量，我们不写进配置、不进产出目录。

TA 拿不定主意就说默认是零依赖、以后随时能换（改 MCP 启动参数就行），别催他选云端——**维护者自己偏向云端，但那是个人偏好，不是产品推荐**。

### 第 6 步：出货

```bash
python memory_init.py --out <产出目录> --step ship --client claude-code
python memory_init.py --out <产出目录> --step ship --client codex
python memory_init.py --out <产出目录> --step ship --client grok
python memory_init.py --out <产出目录> --step ship --client generic
```

四条命令只选与客户端相符的一条：Claude Code 产出 `CLAUDE.md`，Codex 产出
`AGENTS.md`，Grok Build 产出 `.grok/agents/companion.md`，通用／自建前端产出
`persona.md`。四档都会同时产出
`memory/`、`mcp-config.json` 与 `引导句.txt`；generic 档还会复制一份《注入契约》。

⚠ **别把 `<产出目录>/memory` 整体当成 TA 的叙事记忆库去接**：走七步走时，叙事语料
仍在 TA `--corpus` 指的目录；产出包在 `memory/index/` 创建独立索引摘要目录，并由
`mcp-config.json` 的 `--index-dir` 合并读取。`README.txt` 只是写法说明，不算摘要；
只有出货时加 `--import <导出文件>`、由我们替 TA 建库，窗口文件才落进 `memory/timeline/`。
如果 inspect 时给过外部 `--corpus`，ship 又显式给 `--import`，以本次导入为准：配置里的
`--corpus` 改指 `<产出目录>/memory`，外部目录保持只读；不要把导入后的服务继续接回旧目录。
`引导句.txt` 是闭源前端可用的一行指针，不是另一份人格文件；Claude Code／Codex／Grok Build
用不上它。

**⚠ 往同一个产出目录出第二遍货时会被拦一次**：`memory/timeline/`
里已有的窗口如果会被这次改样，出货会停下来并报 `CORPUS_TIMELINE_OVERWRITE`。
**这不是出错，是在保护 TA 的记忆**——`latent_search` 那支笔（`latent_append`）写回的
新窗口就长在那些文件里，盖掉取不回来：人格文件能重新生成，记忆不能。
两条出口，照 TA 的意思挑一条重跑本步：

- `--backup-corpus`：先把整个 `timeline` 备份成 `timeline.bak` 再写（**只加不减**，
  已有备份就顺号成 `timeline.bak2`，我们不会删任何一份）。**拿不准就用这条。**
- `--accept-corpus-overwrite`：TA 明确说了「就是要覆盖」再用。

想留着现在这份记忆库不动，**换一个 `--out` 目录**就行——没有专门的开关做这件事。
⚠ 第一次出货、以及同一份语料原样重跑（写出来跟磁盘上一模一样）**都不会被拦**：
判据是「内容会不会变」，不是「目录空不空」。

### 第 7 步：接入客户端

```bash
claude mcp add memory --scope user "--" python <src绝对路径>/mcp_server.py --corpus <产出目录>/memory --threads <产出目录>/threads.jsonl
```

三个踩过的坑，提醒 TA：

- **PowerShell 会吞掉裸的 `--`**，必须像上面这样带引号写成 `"--"`。
- **不加 `--scope user`** 的话配置只对当前目录生效，换个目录起会话就找不到了。
- 路径用正斜杠 `/`，Windows 一样认，省掉转义麻烦。

### 第 8 步：验证

让 TA **开一个全新会话，并且从产出目录起**（人格文件在那儿才会被读到），第一句问一件只有 TA 们的历史里才有的事，**别提任何工具字眼**。

-  接通了：模型主动查了记忆再回答。
- ❌ 没接通：模型说"我没有相关记录"。

没接通时按顺序查：会话是不是起在产出目录里（这是最常见的原因）→ `claude mcp list` 里 memory 服务连着没有 → **跑一次部署体检**（下面这条），别靠反复换问题去猜。

⚠ **`claude mcp list` 显示  Connected 不等于连的是这一份语料**：
`memory` 这个服务名会撞车——`claude mcp add memory --scope user` 遇到同名已存在时报
`MCP server memory already exists in user config`，**它没有覆盖（这是对的），但也没接上**，
而这里的  Connected 连的是**旧的那个**。服务在、名字对、连接正常，只是记忆库是别人的。
**所以这一格要问的不是「memory 连着没有」，是「memory 指的是不是这一份语料」——
判据是 `--doctor` 打出来的那个绝对路径，跟你的产出目录对一对。**
⚠ 绕开撞车的办法：不动 user 作用域，改在产出目录放 `.mcp.json`（项目作用域），
这跟 `CLAUDE.md` 本来就按目录生效的语义一致。

```
python <src路径>/mcp_server.py --doctor --corpus <TA的叙事语料目录> --index-dir <产出目录>/memory/index --threads <产出目录>/threads.jsonl
```

它把“配好了没有”单独拆出来回答：**它实际读的那个绝对路径**（配置里写的是相对值时会解析开，“我以为它读的是别处”就是这么来的）、语料读到没有、指错层没有（人格文件混进语料这种它认得出）、**语料的时间范围**（第 0 步那个旧快照的坑，部署之后只有这里还会让它现形）、时间戳成色、sidecar 接上没有、语料目录写不写得进去、握手与工具表，以及拿语料自己的标题回查一次。`✗` 先修完再起服务，`⚠` 是“能用但会悄悄变差”。**体检只读，跑完 TA 的语料目录里不会多出任何文件**，所以放心在排查现场跑。（`--embed` 档不体检，报告里会照实说明。）

## 三·五、检索路线：这一节讲第 5 步之后的事

第 5 步已经让 TA 选过一次路线了（三条路 + 各自的代价）。这一节是给你留的两样东西：**选完之后要不要回头再问一次**，以及**三条路线共同的一条诚实话**。

**为什么第 5 步要当场问、而不是等 TA 用一阵子再说**：分两半看。**性能取舍**（快一点 vs 慢一点、装不装依赖、下不下 100MB 模型）确实可以后置，为它打断一个刚上手的新用户不值得。但**语料去哪儿不是性能取舍**：它不可逆，发出去就收不回来。所以——

- **性能取舍仍然可以后置**：零依赖和本地模型之间怎么选，TA 用一阵子觉得"它有时候找不到我明明说过的事"再回头换，完全来得及；
- **语料去向必须当场问**：只要选项里有一条会把私人记忆发出本机，就不能靠"TA 以后自己去读文档"。

这不是我们出尔反尔，是那条决定当初权衡的东西变了。

**什么时候回头再问一次**：TA 抱怨"它记得那件事，但我换个说法问就找不到了"——这是词面检索的典型症状，值得提一句可以换到本地模型或云端；反过来，TA 没抱怨就别主动推销，默认档本来就够用。换路线不用重跑初始化，改 MCP 启动参数即可（`--embed`，云端再加 `--embed-provider cloud`）。

**云端档有一件事你要替 TA 记着**：换了 embedding 模型，"有没有查到"的判定门槛必须重新标定。没标定过的模型我们不给假数字——那种情况下向量路只参与排序、不单独放行候选，服务启动时会明说"未标定"。看到这句话不用慌，它是诚实，不是故障。

**一条重要的诚实话，三条路线都适用**：**这套东西目前不擅长说"我没有这条记忆"。**
理想情况下，TA 问一件从没记录过的事，系统该查不到、AI 该如实说没找到。我们拿一份
真实规模的记忆库（六百多块）实测过：**无论哪条路线，这件事都做得不好**——尤其
当 TA 问的是"像是记过、其实没记"的日常事（某次复诊约在几号、某张单子多少钱），
系统几乎总能捞回几条沾边但不相干的记录。

这对你意味着一件具体的事：**检索返回了东西，不等于那就是答案**。如果捞回来的几条
跟 TA 问的对不上，**最多换一种更具体的说法再查一次**：第二次调用仍把原问法放在
`query`，把泛称换成名字、物件、地点，或补上记录里当时可能用过的词后放进
`queryVariant`。服务端会保留原问法并融合两路结果，不让改述直接覆盖原意。第二次仍然
对不上，就直说这件事库里可能没记；不要继续循环检索到“看起来像有”为止，也**不要拿
沾边的记录去圆**。
这一条比"多答对几个问题"重要——记忆产品编造出来的"记得"，比承认不记得伤害大得多。

（这里如实告诉你现状，不粉饰。）

## 四、接下来 TA 该知道的事

装完不是结束，告诉 TA 这几件：

1. **记忆库会自己长**。模型有一个写回工具（`latent_append`），对话里出现值得记的事会当场写进去，不用 TA 操心。
2. **人格文件是 TA 的**，随时可以自己改。改重了、改具体了都好——它一开始比较短是正常的，东西是慢慢长出来的。
   ⚠ **只有一处要提醒**：改的时候别删 `##` 标题行。归节靠标题做锚点，删一行标题会让那一节的正文顺延塌进上一节。真删了也不会没声——下次 `--step inspect` 会摊开「上次 N 块 → 这次 M 块」的差异表，整节塌空直接拦下（见第 1 步）。⚠ **但这只在「已经跑过一次、有基线可比」时成立**：第一次跑就删错、或产出目录被删掉重来，都没有上一次可比，照旧静默（同见第 1 步那条边界）。
3. **新增记忆正文必达，索引必须闭环**。`latent_append` 交付正文、当下状态和 `indexEvidence[{type,quote}]`；quote 只摘原文，type 取 event／feeling／reason／state／context。服务端统一渲染索引，不再让模型猜日期、粗体和两行四段。证据不合格时正文照常写进 timeline，回执给 `recordId` 与 `indexStatus=pending`；之后仍用 `latent_append`，只传 `recordId＋indexEvidence` 补索引，绝不重复正文。服务端只容忍空白、全半角与引号标点形态差异，最终进入 index 的始终是重新定位出的原文。配了独立 `--index-dir` 就写到该目录；旧部署未配时兼容写到 `<corpus>/index/` 并在回执提醒升级。检索层在 timeline 与 index 都有可靠候选时至少各保留一条，避免短摘要整层挤掉原始记录。`README.txt` 不进库；旧 `indexSummaries` 只作兼容。
   这里的只读承诺专指 ship 与 `--doctor` 不改语料；`latent_append` 属运行期写回。
   兼容落点只在未配 `--index-dir` 时生效，且只新增自动摘要，不迁移、不复制、
   不覆盖、不重排已有 `<corpus>/index/` 文件。

## 五、如果出问题

- 每个 `src/*.py` 都能单独自检：`python <文件名> --selftest`，全绿说明零件正常。
- `python e2e_smoke.py --selftest` 一口气跑完从导入到检索的整条链，红了会指出断在哪一环。

- `python mcp_server.py --doctor --corpus <TA的记忆库目录> --index-dir <产出目录>/memory/index --threads <threads.jsonl>`
  体检这一份**部署**（不是代码）：语料读到没有、指错层没有、时间戳成色、sidecar、
  写回落点、握手，以及拿语料自己的标题回查一次。只读，跑完 TA 的目录里不会多出文件。

排障时先跑这三个，能快速区分“是代码坏了”“是这条链断了”还是“是这一份配置的问题”——
前两个查代码，第三个查配置，别拿一个的结论去解释另一个。
