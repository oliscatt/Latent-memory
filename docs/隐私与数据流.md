# 隐私与数据流

Latent 默认把人格与记忆留在用户控制的文件系统里，但“存储在本地”不等于“任何内容都不会
离开本机”。本页按阶段写清数据落在哪里、什么时候可能发给第三方，以及删除到底删了什么。

## 数据分类与落点

| 数据 | 常见落点 | 内容性质 |
|---|---|---|
| 人格文件 | `CLAUDE.md`、`AGENTS.md`、`.grok/agents/companion.md` 或 `persona.md` | 高度敏感；身份、关系、相处方式与来源片段 |
| 记忆正文 | 默认 `<corpus>/timeline/*.md`，配了 `--write-dir` 则在它指向的目录 | 高度敏感；历史事件与当下状态 |
| 索引摘要 | 独立 `--index-dir`，未配置时兼容写入 `<corpus>/index` | 敏感；正文的检索指针与摘要 |
| 会话线索 | `threads.jsonl` | 敏感；上次聊到哪与未完事项 |
| 初始化状态 | `init_state.json`、`persona-extraction/` | 敏感；回答、候选、来源路径、哈希与确认结果 |
| 检索与自动浮现 sidecar | `.weights.json`、`.retractions.json`、`.supersessions.json`、`.entities.json`、`.embed_cache.json`、`.passive.json` | 不等同正文，但包含行为、关系、变迁时间、原文范围、触发许可或内容指纹 |
| 客户端配置 | `mcp-config.json` | 路径与启动参数；不应含云端 API key |
| 自动浮现观测 | 宿主显式指定的本地 JSONL；默认不存在 | 不含输入、证据或回答；含散列会话、阶段状态、原因码、耗时和用量 |

仓库 `.gitignore` 会挡住常见产出，但它不是数据保险箱。产出目录应放在用户自己的私有目录或
私有仓库，不要依赖忽略规则替代权限控制。

## 三条检索路线

| 路线 | 语料与查询是否发给 embedding 服务 | 额外说明 |
|---|---|---|
| `zero-dep` | 否 | 只用 Python 标准库 |
| `local` | 否 | `fastembed` 首次可能联网下载模型；推理数据留在本机 |
| `cloud` | 是 | 语料块建索引时发送，查询时也发送；适用所选服务商的政策 |

云端 key 只从环境变量读取。不要把真实 key 写进 `mcp-config.json`、人格文件、shell 历史、
issue、截图或测试报告。

## 初始化阶段

默认初始化不会把语料自动上传给本项目的服务器。需要模型提炼候选时，工具优先生成任务包，
由用户决定拿到哪个模型处理；把任务包交给云端模型，就等于把其中的来源内容交给该服务商。

使用 `--import` 处理 ChatGPT／Claude 导出包时，解压后的文件、候选结果和最终人格都应按原始
导出包的敏感级别保管。不要把真实导出包当公开 bug 夹具。

## 运行阶段

### 本机 stdio

MCP 进程、语料和 sidecar 都在本机。宿主调用检索后，返回片段会进入宿主模型的上下文；如果
宿主模型在云端，召回内容仍会发送给该模型提供方。

### 回环 HTTP

只绑定 `127.0.0.1` 时，别的机器不能直接连接，但同机进程仍可访问。回环无 token 是对同机
环境的信任，不是进程级权限隔离。

### 远程 HTTP

非回环绑定必须配置 Bearer token，但服务本身只提供裸 HTTP，不负责 TLS。推荐让服务继续绑定
回环，由反向代理终止 HTTPS、鉴权和限流。远程部署意味着语料与 sidecar 位于那台服务器，
客户端请求和返回正文也会经过网络。

服务端对被拒请求只记录方法、去掉 query 的路径、来源 IP 与拒绝原因；不记录 token、请求体、
问句或记忆正文。正常请求默认不打访问日志。反向代理和云厂商可能有自己的日志策略，需要另查。

## 自动浮现的数据边界

Passive Recall 自动浮现默认关闭。启用后，宿主会在每轮用户消息之后、首个模型请求之前，把
当前输入和少量上下文证据交给 Latent 的隐藏入口；合格时返回少量记忆原文与必要修订，再由宿主
决定注入位置。**支持 MCP 不等于具备这条宿主链路。**

**自动浮现的检索与注入路径只读记忆库：不改记忆正文、索引、权重、撤回或事实变迁账本。**
`.passive.json` 只在正常 `latent_append`／`latent_supersede` 写回时随既有校验增量更新，不是
每轮自动检查产生的暗写。

两种模式的数据留存不同：

- 临时模式只把自动资料放进本轮请求副本；合格宿主不得把它带进正常 history、保存、恢复、
  分叉或压缩输入；
- 历史保留模式会把自动资料追加进对话历史，后续请求、保存、恢复或压缩可能继续携带；关闭开关
  只停止新增，不会自动删除已有文本；
- 模型已经生成的自然语言回答属于普通对话历史，两种模式都不承诺替客户端删除。

宿主可显式设置 `PASSIVE_RECALL_OBSERVATIONS=<本地 JSONL 路径>` 保存脱敏观测。未设置就不
写；观测不含用户输入、历史证据、模型回答或凭证，会话与 delivery 只留散列。反向代理、聊天
模型提供方和宿主自身仍可能有独立日志，不能用 Latent 观测白名单替它们背书。

自动浮现异常时先关闭；主动检索、换窗召回与正常写回不受影响。最坏情况是错误或过期资料已
留在宿主历史，而不是记忆库被改坏。能控制 history 的宿主应移除；不能移除时，开一个不继承
旧片段的新会话。完整步骤见 [`自动浮现.md`](自动浮现.md)。

## 事实变迁、纠错与删除

`latent_supersede` 用于当时真实、后来变化的事实。旧正文不会被改写；关系账本
`.supersessions.json` 保存新旧 `recordId` 的双向链接、状态和 Latent 登记变化的时间。
旧记录默认不返回，但历史意图查询仍可展开整条链，因此这不是删除手段。

`latent_correct` 只用于旧说法从未真实过的纠错。它会写撤回关系，并让旧记录在包括历史查询
在内的所有检索中消失，但不会从 `timeline/*.md` 擦掉原始文字，也不会清除备份、Git 历史、
客户端聊天记录或第三方模型日志。

`latent_cleanup` 是更窄的正文清理口：只接受 Latent 自己写回时返回的稳定 `recordId`，先纯读
预览，再用绑定当前文件快照的确认令牌删除一条；关联索引和受影响 sidecar 同步处理，未解决
事项仍引用时拒绝。它会先把原字节放进 `<corpus>/.cleanup-trash/`，所以是“退出活动语料”的
可恢复清理，不是合规意义上的彻底销毁；隔离副本、Git 历史和第三方副本仍须分别处理。

需要把没有稳定 `recordId` 的导入语料真正删除，或连隔离副本也要销毁时：

1. 先停止 MCP 服务，确认操作的是哪个产出目录；
2. 备份仍需保留的内容；
3. 删除或编辑目标 `timeline` 文件，并一并检查索引摘要、`threads.jsonl`、相关 sidecar、
   `persona-extraction/`、`init_state.json` 与 `timeline.bak*`；
4. 如果内容曾进入 Git，按仓库托管方的历史清理流程处理，普通新 commit 不能抹掉旧历史；
5. 如果内容曾发送给聊天模型、embedding 服务、反向代理或云服务器，按各方的数据删除流程处理；
6. 重启后运行 `mcp_server.py --doctor`，再用不会暴露原文的查询确认目标内容不再返回。

删除是不可逆操作。不要对不确定的目录执行批量删除；先用 `--doctor` 核对绝对路径。

## 公开报告与测试

- 公开测试只使用合成语料，不读取用户产出目录。
- 报告问题时优先写最小虚构复现；真实语料只给聚合数字，不给题面、正文或人格 diff。
- GitHub 私密漏洞报告也不要上传敏感附件；附件直链可能脱离报告可见性。
- JSON 测试报告记录环境和退出结果，不包含 token、语料或人格文件。
