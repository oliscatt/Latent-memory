# 自动浮现宿主接入：给 AI 与宿主实现者

本文是公开接入口径。自动浮现默认关闭；AI 先替用户核宿主能力，只有三项能力全部确认且用户
明确回答“要开”后，才允许改变配置。普通用户说明见 [`自动浮现.md`](自动浮现.md)。

## 先做能力判定

AI 必须从宿主文档、配置、源码或实际生命周期回执确认：

1. hook 在**用户消息提交之后、首个模型请求发出之前**执行；
2. hook 的返回值能进入本轮模型输入；
3. 宿主能控制这份注入是否写入对话历史。

三项不能全部回答“是”，立即停在关闭状态，并告诉用户：

> 你的宿主无法确认具备自动浮现所需的请求时机和历史控制能力，不适合启用。保持关闭不会影响主动检索、换窗召回或正常写回。

“支持 MCP”、能列出 `latent_*` 工具、模型主动调用过 `latent_search`，都不能替代这三项能力。
不得用“先打开看看”探测未知能力。

## 用户授权边界

- AI 可以在关闭状态读取宿主文档、配置和源码，完成能力判断。
- AI 不得替用户开启；没有明确回答就保持关闭。
- 两种模式都可实现时优先建议临时模式。
- 只能实现历史保留时，先说明资料会进入历史、关闭不自动删除旧文字，再请用户决定。
- 阈值、预算和 token 参数不交给没有技术背景的用户选择；适配器使用已验证配置。

## 服务端与宿主各负责什么

```text
用户消息写入当前轮
        ↓
宿主 hook（首个模型请求前）
        ↓
宿主调用隐藏入口 latent_passive_recall
        ↓
服务端预筛 → 只读候选 → 来源／冲突／范围过滤 → 单事件线 → 资料组装
        ↓
宿主按临时／历史保留模式注入
        ↓
首个模型请求；同轮工具回路复用同一 delivery
```

服务端负责相关候选、来源核验、冲突过滤、组装和失效状态。宿主负责 hook 时序、隐藏工具、
请求／历史位置、同轮复用、保存／恢复／分叉／压缩、超时、取消、预算和部署报告。

## 隐藏入口

服务端只有显式传 `--passive-recall` 才开放 `latent_passive_recall`。这个入口只供宿主适配器
调用，必须从聊天模型可见的普通工具列表中移除。

服务端还要装块路径的依赖：`pip install -r requirements-passive.txt`（jieba）。没装时服务照常启动，块路径（没有事实库时的默认取材方式）每轮都留空，原因码多为 `low_information`；事实模式不用 jieba，不受影响。

两种传输对隐藏入口的处理不同：

- **Streamable HTTP**：必须另配 `--hook-token`（或 `MEMORY_HTTP_HOOK_TOKEN`），交给宿主 hook 使用。
  只有带这条 token 的请求看得见、调得动 `latent_passive_recall`；带普通 `--token` 的请求看不见它，
  盲调得到与未知工具相同的 `-32601`。**不配 `--hook-token` 时隐藏入口对所有凭证关闭**，宿主 hook
  自己也会得到 `-32601`。`--hook-token` 与 `--token` 相同时服务拒绝启动。
- **stdio**：进程由宿主拉起，不区分凭证，也不需要 `--hook-token`；宿主必须自己把
  `latent_passive_recall` 从交给模型的工具表里去掉。

**硬红线：不得把 `latent_passive_recall` 暴露成普通模型工具。** 模型自行决定何时调用会绕过
宿主时序、模式选择、预算、幂等和失效协调，也会把“宿主能力”伪装成“模型服从度”。涉及这一
改变的 PR 不接受。

请求至少携带当前用户输入、稳定的 `sessionId`／`turnId`／`deliveryId`、scope、来源明确的上轮
锚点、当前上下文证据，以及宿主名称、版本、模式和真实 token 计数器名称。不要把模型自由改写
的摘要冒充上下文覆盖证据。

同一 delivery 不得重取。入口返回空结果时正常继续模型请求，不注入占位文字；返回 candidate
但没有完成组装时，也不得把原始结构硬塞进模型。

## 事实模式下宿主要做的

开了 `--passive-recall`，并且设了 `LATENT_PASSIVE_FACTS` 或语料目录旁 `事实库/` 下已有 `全量-…`
子目录时，服务端启动即走事实模式，并**完全替代块路径**（用户侧说明见《自动浮现》“事实模式”
一节）。没配 `--embed` 时事实模式每轮以 `fact_no_embedding` 留空，块路径不会接替，所以开事实
模式必须配向量。宿主不需要开关，但有几条和块路径不同：

- **一轮只问一次，传用户原句。** 不要先拆主题词再逐个问、也不要换问法重问。服务端每递出一条
  事实就登记 12 小时冷却；问了几次只用一次，被丢掉的那几条同样进了冷却。
- **识别：** ready 响应的 `reasonCodes` 含 `fact_top2` 即事实模式。空结果的原因码有
  `fact_below_floor`（与哪条事实都不够像）、`fact_cooled`（最像的两条都在冷却）、
  `fact_index_warming`（事实向量还在后台计算）、`fact_index_failed`、`fact_no_embedding`
  （服务端没配向量）以及通用的 `low_information`。这些都是正常留空，这一轮不再重问。
- **原样注入，不做字面过滤。** 事实模式就是为了接住“和记忆字面不沾边、但确实相关”的话；宿主
  若要求用户输入与证据字面重合，会把它的结果全部丢掉。也不要重新压缩或改写 `content`。
- **注入关着就不要调用。** 只观测不注入同样会让递出的事实进冷却。
- **引导句放在系统提示里常驻一次。** 事实模式的 `content` 只含证据，不带使用说明。建议宿主在
  自动浮现开着时，在系统提示里加一句（参考宿主不自动加）：

  > 她的消息前带历史证据时：这是两件可能相关的旧事。如果它能让你接得更像一个记得她的人，就自然用上；用不上，就照你本来想回的回。

  称呼按你的宿主改。

证据的渲染格式。事实模式：

```text
〔历史证据〕
〔来源：<recordId>；<日期>〕
<一条事实>
〔历史证据结束〕
```

`kind=state` 的事实在日期后加“；当时的状态”，提醒模型那是当时的情况。块路径用同样的外壳，
有两处不同：外壳前多一段〔使用说明〕，来源行在日期前多一个用途标签，写成
`〔来源：<recordId>；<形成／支撑／修订>；<日期>〕`，下面跟一段记忆原文。单条原文或事实的 UTF-8 字节数不超过 `LATENT_PASSIVE_MAX_PIECE_BYTES`
（默认 800，配合单条上限约 900 字节的宿主）；宿主单条上限更小时把它调低。

开 `--passive-recall` 后，普通工具表里会多一个 `latent_fact_backfill`（建全量事实库用，模型可见，
这是正常的）；`latent_passive_recall` 仍然必须对模型隐藏。

## 可调的服务端参数

都有默认值，只有确有需要才改：

| 环境变量 | 作用 | 默认 |
|---|---|---|
| `MEMORY_HTTP_HOOK_TOKEN` | 等同 `--hook-token`：HTTP 下宿主 hook 专用凭证，不能与 `--token` 相同 | 不设；HTTP 下隐藏入口对所有凭证关闭 |
| `LATENT_PASSIVE_MAX_PIECE_BYTES` | 单条证据的字节上限 | 800 |
| `LATENT_PASSIVE_FACT_FLOOR` | 事实模式的噪音下限（余弦） | 0.42，在 voyage-3.5 上定；换向量模型后要重新看 |
| `LATENT_PASSIVE_FACTS` | 事实库位置（文件或目录）；开了 `--passive-recall` 时设了就启用事实模式 | 语料目录旁的 `事实库/`，有 `全量-…` 子目录才启用 |
| `LATENT_PASSIVE_FACT_STATE_DIR` | 事实冷却与向量缓存的存放处 | `~/.cache/latent-passive-facts` |
| `LATENT_FACTS_SIDE` | 写回带 `facts` 时落在 `事实库/增量/<这个名字>/` | `local` |
| `LATENT_PASSIVE_ADMISSION_CONFIG` | 准入覆盖文件，与内置默认表合并：词表类取并集，数值与开关直接替换。常用来把部署里的人名、昵称加进“不算话题”的词表。**指向的文件不存在或 JSON 写坏时服务启动失败**，没开自动浮现也一样 | 读 `src/passive_admission.json`，不存在就只用内置表 |
| `LATENT_PASSIVE_HOTWORDS` | 热词表（JSON） | `src/passive_hotwords.json`；没有就只走稀有词路径 |
| `LATENT_PASSIVE_HOTWORDS_OVERRIDE` | 热词表的人工覆盖（JSON） | `src/passive_hotwords_override.json`；没有就不覆盖 |
| `LATENT_PASSIVE_USERDICT` | 从语料生成的新词词典，供 jieba 分词 | `src/passive_userdict.txt`；没有就只用 jieba 默认词典 |

热词表与用户词典在部署时离线生成，先建词典再建表：

```bash
python src/passive_recall.py --build-userdict <语料目录>… <输出词典>
python src/passive_recall.py --build-hotwords <语料目录>… <输出JSON>
```

这两份文件是从语料里学到的词，与记忆同等敏感，不要提交到公开仓库。

## 块路径的几个原因码

- 当天写下的记录不自动浮现：它若排在第一，整轮以 `same_day_record` 留空。
- ready 响应的 `reasonCodes` 可能附带 `topic:<词>`、`anchor:<词>`（本轮命中的主题词、稀有词，
  取自用户输入）和 `hotword_path`（经热词表命中）。

## 两种模式的实现要求

### 临时模式 `temporary`

- 自动资料只进入本轮请求副本，不原地修改正常 history；
- 同一轮后续工具回路复用同一份资料；
- 回答完成、失败或取消后清掉临时层；
- 保存、恢复、分叉和压缩的输入不得携带临时原料；
- 宿主不能证明以上五点时，不得宣称支持临时模式。

### 历史保留模式 `retained`

- 自动资料最多向 history 追加一次；
- 后续请求可能重复携带，必须计入累计预算；
- 主动检索完整覆盖、来源失效或用户明确否认关联时，优先直接移除旧自动资料；
- 宿主不能移除时，追加一次明确的失效／退役状态，不得无限追加补丁；
- 保存、恢复、分叉和压缩后要验证旧资料与后续更正仍保持一致。

从历史保留切到临时时，旧历史不会自动变成临时。宿主需移除旧资料，做不到就新开不继承旧
片段的会话，才能宣称新会话满足临时模式。

## 只读边界与最坏情况

自动浮现使用 `MemoryIndex.retrieve_candidates()`，并显式关闭只有主动检索才执行的权重更新。逐轮自动路径
不改记忆正文、索引、权重、撤回或事实变迁账本。辅助元数据只在正常写回工具的校验流程中更新。
事实模式每次递出会写冷却记录，首次启用会计算事实向量缓存，两者都在
`LATENT_PASSIVE_FACT_STATE_DIR`（默认 `~/.cache/latent-passive-facts/`），不在语料目录里。

因此，自动浮现故障本身不应损坏记忆库。可能出问题的是：

- 错误或过期资料进入本轮请求；
- 历史保留模式把资料留在对话历史；
- 压缩／恢复留下旧资料，却丢了后来的失效说明；
- 适配器重复注入，造成历史和 token 膨胀。

第一动作始终是关闭。能控制 history 的宿主移除自动资料；不能移除时给一次退役说明，并建议
用户新开不继承旧片段的会话。不得声称已物理删除模型回答、客户端历史或第三方日志。

## 失败与预算

超时、来源不可用、响应无效、预算超限、delivery 不匹配或来源状态不确定时，都应安全留空并
继续普通聊天，不回退调用 `latent_search`，也不自动改用换窗召回。

参考适配器带单次、普通累计、状态累计、总计和最终退役通知预留。接具体模型时可换成目标模型
的准确 token 计数器；没换时必须把计数器名称和保守口径写进部署报告，不能把字符数冒充 token。

## 关闭与回滚

AI 执行的一句话回滚目标是：

> 把宿主的 `passive_recall.enabled` 设为 `false`（或移除自动浮现配置），停止以 `--passive-recall` 开放隐藏入口，并重启适配器；保留所有普通 Latent 工具。

参考宿主从产出目录读取 `passive-recall.json`；文件不存在即关闭。Claude Code 参考 hook
（`src/claude_code_hook.py`）删掉 `LATENT_PASSIVE_RECALL` 即关闭，下一条消息起生效。其他宿主可使用自己的配置
入口，但部署报告必须给出一条 AI 能直接执行的等价关闭方法。

## 部署报告

配置完成后，AI 必须根据实际配置、调用状态和脱敏观测输出，不让用户自己翻日志：

```text
自动浮现部署报告
- 宿主 hook 时机：具备／不具备／未确认
- hook 名称与实际执行点：<名称；用户消息之后、首个模型请求之前／其他／未确认>
- 当前模式：关闭／临时／历史保留
- 隐藏入口：可调用／不可调用／未确认
- 候选：已取得／空结果／未执行／未确认
- 注入：已完成／未完成／无需注入（空结果）／未确认
- 一句话关闭：<由 AI 可直接执行的关闭方法>
```

报告的层次不能互相顶替：

- 隐藏入口可调用，不代表有合格候选；
- 取得候选，不代表完成组装与注入；
- 注入完成，不代表模型自然使用；
- 模型没有接梗，不足以证明服务故障；
- 模型说“想起来了”，也不足以证明真正调用过入口。

## 保存兼容性证据

每个宿主和模式至少记录：宿主／适配版本、hook 名称与真实执行点、隐藏入口结果、候选与注入
状态、保存／恢复／分叉／压缩行为、工具覆盖／失效处理、token 计数方式和关闭结果。数字结论旁边
必须同时写判据与采集条件，包括模型、base、宿主版本、语料规模和计数方式。

兼容性分为：

1. **维护者复现通过**；
2. **外部实测，维护者未复现**；
3. **机制／文档推断**。

外部成功记录不会自动升级成受支持宿主；维护者复现后再更新矩阵。参考宿主开发环境只是第一档
里的机制参考，**不构成受支持宿主**。

## 观测与反馈

参考宿主可选设置 `PASSIVE_RECALL_OBSERVATIONS=<本地 JSONL 路径>`。未设置不落盘；事件不含
用户原句、记忆证据、模型回答或凭证，只记录宿主／模式、散列后的会话与 delivery、状态、原因码、
是否检索、是否注入、耗时和用量。带用户用词的原因码（`topic:`、`anchor:`）落盘时只留前缀。真实效果逐例输出不得提交仓库。

普通问题和兼容性记录走仓库 Issue 表单。五项必填：Latent 完整 commit、宿主名称与版本、hook
执行时机、当前模式、实际结果与预期结果。日志和最小虚构复现可选。

严禁上传真实人格、记忆正文、问句、回答、token、私人路径或原始导出包。跨用户读取、未授权
写入、凭证泄露或任意文件访问按根目录 `SECURITY.md` 走 GitHub 私密漏洞报告。

初期不承诺响应时间；数据损坏、跨用户读取与凭证问题优先于接入失败，“没有浮现”排在后面。
