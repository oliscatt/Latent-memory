# 自动浮现宿主接入：给 AI 与宿主实现者

本文是公开接入口径。自动浮现默认关闭；AI 先替用户核宿主能力，只有三项能力全部确认且用户
明确回答“要开”后，才允许改变配置。普通用户说明见 [`自动浮现.md`](自动浮现.md)。

## 先做能力判定

AI 必须从宿主文档、配置、源码或实际生命周期回执确认：

1. hook 在**用户消息提交之后、首个模型请求发出之前**执行；
2. hook 的返回值能进入本轮模型输入；
3. 宿主能控制这份注入是否写入对话历史。

三项不能全部回答“是”，立即停在关闭状态，并告诉用户：

> 你的宿主无法确认具备自动浮现所需的请求时机和历史控制能力，不适合启用。保持关闭不会影响主动检索、换窗召回或正常写回。

“支持 MCP”、能列出 `latent_*` 工具、模型主动调用过 `latent_search`，都不能替代这三项能力。
不得用“先打开看看”探测未知能力。

## 用户授权边界

- AI 可以在关闭状态读取宿主文档、配置和源码，完成能力判断。
- AI 不得替用户开启；没有明确回答就保持关闭。
- 两种模式都可实现时优先建议临时模式。
- 只能实现历史保留时，先说明资料会进入历史、关闭不自动删除旧文字，再请用户决定。
- 阈值、预算和 token 参数不交给没有技术背景的用户选择；适配器使用已验证配置。

## 子智能体与派生会话

自动浮现只喂给人和主会话之间那一轮。宿主派生出来的会话——子智能体、后台 agent、主会话派活
出去的任务——不在这条边界里，哪怕它们跑在同一个宿主、同一个进程里。

- **`agent/pre-step` 这类时机对子智能体同样触发。** 它挂在 agent 循环的每一步上，主会话和
  子智能体走一步都会触发。子智能体的“最后一条 `user` 消息”是派活方写的任务 prompt，不是人说
  的话；拿它去调隐藏入口，召回的私人记忆就注入给了子智能体，而子智能体常常跑在另一个模型上，
  可能是第三方云端模型，记忆就此送出本机。
- **接入方必须能分清这一轮来自主会话还是子智能体。** 依据只能是宿主给的明确字段或生命周期
  事件（例如“只在子智能体里出现的 id 字段”“只对主会话触发的事件”），不能靠 turn 编号、消息
  长短或 prompt 措辞去猜。依据要写进部署报告。
- **分不清就默认不注入**，这一轮也不调用隐藏入口：只调用不注入同样会把任务 prompt 送进检索，
  事实模式下还会把递出的事实登记进冷却。
- **隐藏入口可以带一个可选字段 `origin` 声明这一轮的来源**：`"main"` 是人和主会话之间这一轮；
  `"derived"` 是子智能体、派生会话，或主会话里不是人说的回合（定时任务、后台任务的完成通知这类）。
  声明为 `derived` 时服务端一律回空（原因码 `origin_derived`）：不检索、不登记交付、不记冷却。
  别的值会被拒绝。不传 `origin` 的请求照旧处理，和加这个字段之前一样。
- `origin` 只是给能分清的宿主一个明确的出口，服务端判断不了宿主说的对不对；没传的时候它也不知道这一轮
  来自谁，不会替宿主挡。**分不清就别注入、也别调，这是对接入方的要求**；能确定是派生、又不方便
  整轮跳过的，就传 `origin: "derived"`。

## 服务端与宿主各负责什么

```text
用户消息写入当前轮
        ↓
宿主 hook（首个模型请求前）
        ↓
宿主调用隐藏入口 latent_passive_recall
        ↓
服务端预筛 → 只读候选 → 来源／冲突／范围过滤 → 单事件线 → 资料组装
        ↓
宿主按临时／历史保留模式注入
        ↓
首个模型请求；同轮工具回路复用同一 delivery
```

服务端负责相关候选、来源核验、冲突过滤、组装和失效状态。宿主负责 hook 时序、隐藏工具、
请求／历史位置、同轮复用、保存／恢复／分叉／压缩、超时、取消、预算和部署报告。

## 隐藏入口

服务端只有显式传 `--passive-recall` 才开放 `latent_passive_recall`。这个入口只供宿主适配器
调用，必须从聊天模型可见的普通工具列表中移除。

服务端还要装块路径的依赖：`pip install -r requirements-passive.txt`（jieba）。没装时服务照常启动；有热词表（可在装了 jieba 的机器上生成后复制过来，见下文热词表一节）就退回子串匹配，ready 响应带 `substring_path`；连热词表也没有时块路径（没有事实库时的默认取材方式）每轮都留空，原因码多为 `low_information`；事实模式不用 jieba，不受影响。

两种传输对隐藏入口的处理不同：

- **Streamable HTTP**：必须另配 `--hook-token`（或 `MEMORY_HTTP_HOOK_TOKEN`），交给宿主 hook 使用。
  只有带这条 token 的请求看得见、调得动 `latent_passive_recall`；带普通 `--token` 的请求看不见它，
  盲调得到与未知工具相同的 `-32601`。**不配 `--hook-token` 时隐藏入口对所有凭证关闭**，宿主 hook
  自己也会得到 `-32601`。`--hook-token` 与 `--token` 相同时服务拒绝启动。
- **stdio**：进程由宿主拉起，不区分凭证，也不需要 `--hook-token`；宿主必须自己把
  `latent_passive_recall` 从交给模型的工具表里去掉。

**硬红线：不得把 `latent_passive_recall` 暴露成普通模型工具。** 模型自行决定何时调用会绕过
宿主时序、模式选择、预算、幂等和失效协调，也会把“宿主能力”伪装成“模型服从度”。涉及这一
改变的 PR 不接受。

请求至少携带当前用户输入、稳定的 `sessionId`／`turnId`／`deliveryId`、scope、来源明确的上轮
锚点、当前上下文证据，以及宿主名称、版本、模式和真实 token 计数器名称；能确定这一轮来源的，
再带上 `origin`（见上面“子智能体与派生会话”）。不要把模型自由改写
的摘要冒充上下文覆盖证据。

同一 delivery 不得重取。入口返回空结果时正常继续模型请求，不注入占位文字；返回 candidate
但没有完成组装时，也不得把原始结构硬塞进模型。

## 事实模式下宿主要做的

开了 `--passive-recall`，并且设了 `LATENT_PASSIVE_FACTS` 或语料目录旁 `事实库/` 下已有 `全量-…`
子目录时，服务端启动即走事实模式，并**完全替代块路径**（用户侧说明见《自动浮现》“事实模式”
一节）。没配 `--embed` 时事实模式每轮以 `fact_no_embedding` 留空，块路径不会接替，所以开事实
模式必须配向量。宿主不需要开关，但有几条和块路径不同：

- **一轮只问一次，传用户原句。** 不要先拆主题词再逐个问、也不要换问法重问。服务端每递出一条
  事实就登记 12 小时冷却；问了几次只用一次，被丢掉的那几条同样进了冷却。
- **识别：** ready 响应的 `reasonCodes` 含 `fact_top2` 即事实模式；带上了同块的兄弟行时另有
  `fact_group`，有状态被标成“较早”时另有 `fact_state_older`。一轮最多 5 条（最像的 2 条＋同块最多 3 条），
  兄弟行只在整段 `content` 不超过 `LATENT_PASSIVE_FACT_GROUP_BYTES`（默认 1000 字节）时才带。空结果的原因码有
  `fact_below_floor`（与哪条事实都不够像）、`fact_cooled`（最像的两条都在冷却）、
  `fact_index_warming`（事实向量还在后台计算）、`fact_index_failed`、`fact_no_embedding`
  （服务端没配向量）以及通用的 `low_information`。这些都是正常留空，这一轮不再重问。
- **前两名分差只供参考。** ready 响应的 `reasonCodes` 末尾有一个 `fact_margin:<分差>`：排除写入日不早于今天、
  来源块不现行的事实之后，最像的第 1 名减第 2 名的余弦，不看下限和冷却；只剩一条候选时没有它。服务端不拿它挡，
  宿主想按它决定注不注入，先用下面的标定工具在自己的事实库上量（`sweep --margins`）。
- **原样注入，不做字面过滤。** 事实模式就是为了接住“和记忆字面不沾边、但确实相关”的话；宿主
  若要求用户输入与证据字面重合，会把它的结果全部丢掉。也不要重新压缩或改写 `content`。
- **注入关着就不要调用。** 只观测不注入同样会让递出的事实进冷却。
- **引导句放在系统提示里常驻一次。** 事实模式的 `content` 只含证据，不带使用说明。建议宿主在
  自动浮现开着时，在系统提示里加一句（参考宿主不自动加）：

  > 她的消息前带历史证据时：这是几件可能相关的旧事。如果它能让你接得更像一个记得她的人，就自然用上；用不上，就照你本来想回的回。

  称呼按你的宿主改。

证据的渲染格式。事实模式：

```text
〔历史证据〕
〔来源：<recordId>；<日期>〕
<一条事实>
〔历史证据结束〕
```

`kind=state` 的事实在日期后加“；当时的状态”，提醒模型那是当时的情况。同一轮里另有一条同块、
事件日（没填按写入日）更晚的状态事实时，较早那条再加“；这是较早的状态，可能已被更新”；同一天的不标，
只标不删，单独一条旧状态不标。设了 `LATENT_PASSIVE_STATE_SIM` 时，不同块但彼此余弦不低于它的状态事实也这样比。块路径用同样的外壳，
有两处不同：外壳前多一段〔使用说明〕，来源行在日期前多一个用途标签，写成
`〔来源：<recordId>；<形成／支撑／修订>；<日期>〕`，下面跟一段记忆原文。单条原文或事实的 UTF-8 字节数不超过 `LATENT_PASSIVE_MAX_PIECE_BYTES`
（默认 800，配合单条上限约 900 字节的宿主）；宿主单条上限更小时把它调低。

开 `--passive-recall` 后，普通工具表里会多一个 `latent_fact_backfill`（建全量事实库用，模型可见，
这是正常的；设了 `LATENT_FACT_BACKFILL=off` 时不列）；`latent_passive_recall` 仍然必须对模型隐藏。

## 可调的服务端参数

都有默认值，只有确有需要才改：

| 环境变量 | 作用 | 默认 |
|---|---|---|
| `MEMORY_HTTP_HOOK_TOKEN` | 等同 `--hook-token`：HTTP 下宿主 hook 专用凭证，不能与 `--token` 相同 | 不设；HTTP 下隐藏入口对所有凭证关闭 |
| `LATENT_PASSIVE_MAX_PIECE_BYTES` | 单条证据的字节上限 | 800 |
| `LATENT_PASSIVE_FACT_FLOOR` | 事实模式的噪音下限（余弦） | 0.42，只适用于 voyage-3.5；换了向量模型先按下面“换了向量模型：重新标定事实下限”量，别的模型没有默认值 |
| `LATENT_PASSIVE_FACT_GROUP_BYTES` | 事实模式带同块兄弟行时整段 `content` 的字节上限；最像的 2 条不受它限制 | 1000，给单轮上限 1200 字节（含外壳）的宿主留余量；宿主单轮上限更小时调低 |
| `LATENT_PASSIVE_STATE_SIM` | 不同块的两条状态事实算“同一件事”的余弦线；设了才在跨块之间做“较早的状态”标注 | 不设，跨块比较关闭，只在同块里比。要开先在自己的语料上标定：2026.10.04 在 voyage-3.5 上量过，不相干的状态对余弦中位数 0.585、P95 0.690，填 0.6 会误标约四成 |
| `LATENT_PASSIVE_FACTS` | 事实库位置（文件或目录）；开了 `--passive-recall` 时设了就启用事实模式 | 语料目录旁的 `事实库/`，有 `全量-…` 子目录才启用 |
| `LATENT_PASSIVE_FACT_STATE_DIR` | 事实冷却与向量缓存的存放处 | `~/.cache/latent-passive-facts` |
| `LATENT_FACT_BACKFILL` | 设为 `off` 时不给模型 `latent_fact_backfill`（已经有全量、不想让模型自己补拆的部署）；写回说明随之不再要求带 `facts` | 开 |
| `LATENT_FACTS_SIDE` | 写回带 `facts` 时落在 `事实库/增量/<这个名字>/` | `local` |
| `LATENT_PASSIVE_ADMISSION_CONFIG` | 准入覆盖文件，与内置默认表合并：词表类取并集，数值与开关直接替换。常用来把部署里的人名、昵称加进“不算话题”的词表。**指向的文件不存在或 JSON 写坏时服务启动失败**，没开自动浮现也一样 | 读 `src/passive_admission.json`，不存在就只用内置表 |
| `LATENT_PASSIVE_HOTWORDS` | 热词表（JSON） | `src/passive_hotwords.json`；没有就只走稀有词路径（没装 jieba 时则块路径留空） |
| `LATENT_PASSIVE_HOTWORDS_OVERRIDE` | 热词表的人工覆盖（JSON） | `src/passive_hotwords_override.json`；没有就不覆盖 |
| `LATENT_PASSIVE_USERDICT` | 从语料生成的新词词典，供 jieba 分词 | `src/passive_userdict.txt`；没有就只用 jieba 默认词典 |
| `LATENT_PASSIVE_TOPIC_COVERAGE` | 块路径第一道门：用户这句的主题词，同一条记录要命中多大比例才算相关（命中数 ÷ 总数，至少命中 1 个）。热词路径、稀有词路径不过这道门 | 1.0，全部命中。只有两个主题词的句子比例只有 0／0.5／1，0.5～1.0 之间的值对它们都等于 1.0 |
| `LATENT_PASSIVE_CONTEXT_COVERAGE` | 块路径第二道门：用户这句里主题词以外的实质词（动词、名词），同一条记录要覆盖多大比例。**只在零向量档按词算**；开了向量时这道门看原句向量过不过下限，不受它影响 | 1.0，全部覆盖；0 等于关掉这道门。两个覆盖率写成非数字或不在 0～1 之间时服务启动失败 |
| `LATENT_PASSIVE_DIAGNOSTICS` | 设为 `on` 时，块路径以 `no_reliable_candidate` 留空的响应附 `diagnostics`，说明卡在哪道门（见下文“块路径的几个原因码”）。调准入时开，调完关 | 关；不开时响应里没有这个字段 |

### 换了向量模型：重新标定事实下限

0.42 是在 voyage-3.5 上量的（开发集 89 句：砍掉约两成无用递送，该接住的 28 道一道不丢），只对它成立。
不同向量模型的余弦不是一把尺子：有的模型连不相干的事实也普遍在 0.6 以上，0.42 一条都挡不住，几乎每轮都递、
递的多半不沾边；分数整体偏低的模型则会让 `fact_below_floor` 几乎每轮都出现。别的模型我们没标过，不给默认值，
用 `tests/fact_floor_calibration.py` 在自己的事实库上量。它只读，不打印事实正文和原句：

1. 准备一组句子，一行一句，最好取自真实对话：该接住旧事的、闲聊的、短句都要有。取自历史聊天时，行首写
   那句话的日期加一个制表符（`2026-09-01<TAB>句子`），写入日不早于那天的事实就不算；不写按今天算，事后从
   这段对话里提出来的事实会混进来，分数虚高。
2. 以 floor=0 跑事实模式，列出每句最像的 2 条事实的 id 与分数：

   ```bash
   python tests/fact_floor_calibration.py score --facts <事实库> --sentences <句子文件> --corpus <语料> > 分数.json
   ```

   向量提供方与服务用同一套参数（`--embed-provider` 或 `MEMORY_EMBED_*` 环境变量）。准入和排除规则与线上相同，
   只是不设下限、不看冷却。事实库、语料和 `LATENT_PASSIVE_FACT_STATE_DIR` 一律不写，可以直接指向线上那份；
   缓存里没有的事实向量会现算，按条计费的向量服务注意用量。
3. 对着句子文件和事实库按 id 查原文，在 `分数.json` 里给每句前 2 条各加 `"相关": true` 或 `"相关": false`；
   拿不准的写 `null`，不进表、只报条数。标的时候别看分数，免得被它带着走。
4. 扫门槛：

   ```bash
   python tests/fact_floor_calibration.py sweep 分数.json
   ```

   每个下限一行：留下几条、其中相关几条、准确率、相关保留、不相关挡掉、有东西浮上来的句子。下限只挡跟哪件事都
   不沾边的，相关与否仍由回话的模型判断，所以先保相关：0.42 当初就是在该接住的一道不丢的前提下，挡掉尽量多的
   不相关。选好的值设给 `LATENT_PASSIVE_FACT_FLOOR`，重启服务。

   想看前两名分差（`fact_margin`）是不是比下限分得更开，同一份标注再扫一遍分差：

   ```bash
   python tests/fact_floor_calibration.py sweep 分数.json --margins --floor 0.42
   ```

   一句的分差够了，它的前 2 条都留，不够就都不留；`--floor` 是叠在哪个下限之上（不给就只看分差）。两张表的
   表头都有一行 AUC：随手拿一条相关、一条不相关，相关那条分数（或分差）更高的概率，0.5 等于分不开。服务端
   不按分差挡，量出来分得开，由宿主自己决定怎么用。

相关与不相关的分数可能大面积重叠，扫完哪一档都分不开也是结论：下限只能挡掉最不沾边的那部分。
样本少时百分比的误差不小，记结果时把向量模型、句子数和标注口径写在数字旁边。

热词表与用户词典在部署时离线生成，先建词典再建表：

```bash
python src/passive_recall.py --build-userdict <语料目录>… <输出词典>
python src/passive_recall.py --build-hotwords <语料目录>… <输出JSON>
```

这两份文件是从语料里学到的词，与记忆同等敏感，不要提交到公开仓库。

服务端装不了 jieba 时，在另一台装了 jieba 的机器上对同一份语料跑这两条，只把热词表复制到服务端的
`src/passive_hotwords.json`（或 `LATENT_PASSIVE_HOTWORDS` 指向的位置）。服务端只拿表里的热词对用户原句做子串匹配，
用不到用户词典。语料长了、新事件多了，要重新生成、再复制一次，否则新出现的词不会被认出来。

## 块路径的几个原因码

- 当天写下的记录不自动浮现：它若排在第一，整轮以 `same_day_record` 留空。
- ready 响应的 `reasonCodes` 可能附带 `topic:<词>`、`anchor:<词>`（本轮命中的主题词、稀有词，
  取自用户输入）、`hotword_path`（经热词表命中）和 `substring_path`（服务端没装 jieba，热词是对原句做子串匹配找到的）。
- 开了 `LATENT_PASSIVE_DIAGNOSTICS=on` 时，以 `no_reliable_candidate` 留空的响应多一个 `diagnostics`，是一串和原因码同形的短码，
  只含计数和用户这句话里的词，不含记录内容：`path:<topic_gate／hotword／rare_word>`（走了哪条取材路径，只有 `topic_gate`
  过两道门）、`candidates:<n>`（候选几条）、`admitted:<n>`（过了门的几条），走 `topic_gate` 时再加主题命中最多的那条候选的
  `topic_hits:<命中>/<总数>`、`topic_missing:<词>`（它没命中的主题词）和 `uncovered:<词>`（它没覆盖到的实质词，只在零向量档列）。
  词最多列 8 个，每个最多 16 字。常见的用法：`uncovered:` 里是语气词就加进准入覆盖文件的排除表；是“显示”“浮现”这类
  句子本身的动词、或 `topic_missing:` 里是分词切错的半截词，就要靠上表两个覆盖率。

## 两种模式的实现要求

### 临时模式 `temporary`

- 自动资料只进入本轮请求副本，不原地修改正常 history；
- 同一轮后续工具回路复用同一份资料；
- 回答完成、失败或取消后清掉临时层；
- 保存、恢复、分叉和压缩的输入不得携带临时原料；
- 宿主不能证明以上五点时，不得宣称支持临时模式。

### 历史保留模式 `retained`

- 自动资料最多向 history 追加一次；
- 后续请求可能重复携带，必须计入累计预算；
- 主动检索完整覆盖、来源失效或用户明确否认关联时，优先直接移除旧自动资料；
- 宿主不能移除时，追加一次明确的失效／退役状态，不得无限追加补丁；
- 保存、恢复、分叉和压缩后要验证旧资料与后续更正仍保持一致。

从历史保留切到临时时，旧历史不会自动变成临时。宿主需移除旧资料，做不到就新开不继承旧
片段的会话，才能宣称新会话满足临时模式。

## 已知宿主差异

适配器容易踩的宿主差异逐个记在这里，每条写明来源与成色；没列出的宿主不代表没有差异。

### DeepSeek Harness 桌面版

来源：外部兼容报告（issue #38，自写 host 插件挂 `agent/pre-step`），维护者未复现；模式未确认。

- **末尾那条 `user` 消息不一定是用户原句。** 该宿主会把“运行时上下文”作为一条 `user` 角色
  消息追加在 `messages` 末尾，内容以 `Current runtime context.` 开头。适配器直接取最后一条
  `user` 消息，就会把运行时上下文当成用户原句送进隐藏入口，每轮得到 `no_reliable_candidate`。
  取本轮输入时先跳过这类消息，再取真正的用户输入。
- **只改本步请求副本，在实现上是临时注入，但不等于已证明不落 history。** 报告方的适配器只替换
  进入本步的 `messages`、不追加会话事件，却没能从宿主会话日志确认注入有没有被写进历史，所以
  模式记为“未确认”。要宣称临时模式，仍须满足上文临时模式的各项要求，并拿到端到端证据。
- **`agent/pre-step` 对子智能体也触发。** 来源：外部报告（issue #43），维护者未复现。报告方
  日志里 `turn=1` 的几条就是子智能体（每个子智能体新建会话，turn 从 1 数起），每次都注入了
  记忆。能区分主会话与子智能体的宿主字段尚未确认，确认之前按上文“分不清就默认不注入”处理。

## 只读边界与最坏情况

自动浮现使用 `MemoryIndex.retrieve_candidates()`，并显式关闭只有主动检索才执行的权重更新。逐轮自动路径
不改记忆正文、索引、权重、撤回或事实变迁账本。辅助元数据只在正常写回工具的校验流程中更新。
事实模式每次递出会写冷却记录，首次启用会计算事实向量缓存，两者都在
`LATENT_PASSIVE_FACT_STATE_DIR`（默认 `~/.cache/latent-passive-facts/`），不在语料目录里。

因此，自动浮现故障本身不应损坏记忆库。可能出问题的是：

- 错误或过期资料进入本轮请求；
- 历史保留模式把资料留在对话历史；
- 压缩／恢复留下旧资料，却丢了后来的失效说明；
- 适配器重复注入，造成历史和 token 膨胀。

第一动作始终是关闭。能控制 history 的宿主移除自动资料；不能移除时给一次退役说明，并建议
用户新开不继承旧片段的会话。不得声称已物理删除模型回答、客户端历史或第三方日志。

## 失败与预算

超时、来源不可用、响应无效、预算超限、delivery 不匹配或来源状态不确定时，都应安全留空并
继续普通聊天，不回退调用 `latent_search`，也不自动改用换窗召回。

参考适配器带单次、普通累计、状态累计、总计和最终退役通知预留。接具体模型时可换成目标模型
的准确 token 计数器；没换时必须把计数器名称和保守口径写进部署报告，不能把字符数冒充 token。

## 关闭与回滚

AI 执行的一句话回滚目标是：

> 把宿主的 `passive_recall.enabled` 设为 `false`（或移除自动浮现配置），停止以 `--passive-recall` 开放隐藏入口，并重启适配器；保留所有普通 Latent 工具。

参考宿主从产出目录读取 `passive-recall.json`；文件不存在即关闭。Claude Code 参考 hook
（`src/claude_code_hook.py`）删掉 `LATENT_PASSIVE_RECALL` 即关闭，下一条消息起生效。其他宿主可使用自己的配置
入口，但部署报告必须给出一条 AI 能直接执行的等价关闭方法。

## 部署报告

配置完成后，AI 必须根据实际配置、调用状态和脱敏观测输出，不让用户自己翻日志：

```text
自动浮现部署报告
- 宿主 hook 时机：具备／不具备／未确认
- hook 名称与实际执行点：<名称；用户消息之后、首个模型请求之前／其他／未确认>
- 当前模式：关闭／临时／历史保留
- 子智能体／派生会话：能区分（依据：<字段或事件>）／不能区分，已默认不注入／宿主没有子智能体／未确认
- 隐藏入口：可调用／不可调用／未确认
- 候选：已取得／空结果／未执行／未确认
- 注入：已完成／未完成／无需注入（空结果）／未确认
- 一句话关闭：<由 AI 可直接执行的关闭方法>
```

报告的层次不能互相顶替：

- 隐藏入口可调用，不代表有合格候选；
- 取得候选，不代表完成组装与注入；
- 注入完成，不代表模型自然使用；
- 模型没有接梗，不足以证明服务故障；
- 模型说“想起来了”，也不足以证明真正调用过入口。

## 保存兼容性证据

每个宿主和模式至少记录：宿主／适配版本、hook 名称与真实执行点、隐藏入口结果、候选与注入
状态、保存／恢复／分叉／压缩行为、工具覆盖／失效处理、token 计数方式和关闭结果。数字结论旁边
必须同时写判据与采集条件，包括模型、base、宿主版本、语料规模和计数方式。

兼容性分为：

1. **维护者复现通过**；
2. **外部实测，维护者未复现**；
3. **机制／文档推断**。

外部成功记录不会自动升级成受支持宿主；维护者复现后再更新矩阵。参考宿主开发环境只是第一档
里的机制参考，**不构成受支持宿主**。

## 观测与反馈

参考宿主可选设置 `PASSIVE_RECALL_OBSERVATIONS=<本地 JSONL 路径>`。未设置不落盘；事件不含
用户原句、记忆证据、模型回答或凭证，只记录宿主／模式、散列后的会话与 delivery、状态、原因码、
是否检索、是否注入、耗时和用量。带用户用词的原因码（`topic:`、`anchor:`）和 `diagnostics` 里带词的短码
（`topic_missing:`、`uncovered:`）落盘时只留前缀，计数照留。真实效果逐例输出不得提交仓库。

普通问题和兼容性记录走仓库 Issue 表单。五项必填：Latent 完整 commit、宿主名称与版本、hook
执行时机、当前模式、实际结果与预期结果。日志和最小虚构复现可选。

严禁上传真实人格、记忆正文、问句、回答、token、私人路径或原始导出包。跨用户读取、未授权
写入、凭证泄露或任意文件访问按根目录 `SECURITY.md` 走 GitHub 私密漏洞报告。

初期不承诺响应时间；数据损坏、跨用户读取与凭证问题优先于接入失败，“没有浮现”排在后面。
